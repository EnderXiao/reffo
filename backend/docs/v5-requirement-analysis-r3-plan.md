# V5 r3：岗位要求解析与材料条件下的表达质量

状态：用户已批准，分阶段实施中；不是上线声明。日期：2026-09-06。

本文件增补《V5 提示词优化最终方案》r2，不覆盖历史评分、实测及冻结记录。此前 Case3 70/100 保留原评估口径，不因本次定义调整而重算成高分。

## 产品与评估定义

- 源材料充分度：当前提供了什么信息，不等于本人能力上限。
- 岗位匹配程度：有哪些支持、局部支持、客观差距和未知，不是表达质量或录用概率。
- 简历表达质量：在固定真实材料下是否选对重点、表达清楚、保持归属并合理展开。
- 低匹配也可以有好的表达；不为了任一案例满分降低岗位要求、追加模型重写或补造经历。
- 七维权重继续为 25/20/15/10/10/10/10。解释版本为 `material-conditional-quality-r1`；岗位距离单列，不直接扣表达分。“可投递”指无需实质改写，不代表推荐该职位或承诺面试。材料不可评时明确范围受限，不机械给满分。
- 既有事实、隐私、成功率、成本和总体验收门槛不变。新旧稿采用新口径时同场重评；人工评审、原始 JD 标注和完整黄金集仍必须独立完成。

## 内容与展示契约

公开契约 `job-requirement-analysis-v1` 位于 `matching.requirement_analysis`：

1. `portrait`：一句话说明在已知场景下，何种能力与实践有助于承担任务、支持预期结果；综合判断标为 inferred。未知可为 null，不拼凑完美候选人。
2. `tasks/outcomes/successConditions`：任务、绩效方向和成功前提。原文无数值不补 KPI。
3. `attributes`：知识、技能、经验、能力、行为方式、动机与适配；可附期望看到的证据。六维不必填满。
4. `externalRequirements`：学历、年限、工具及明示现实条件，保留优先、例如和替代关系。
5. `unknowns/conflicts`：信息缺失与原文矛盾，不能选择有利版本或判为用户不合格。

条目有 id、text、basis、strength、sourceQuotes、rationale。来源依据 explicit/inferred/unknown，与必要性 necessary/preferred/unspecified 独立；任务推导不会自动升为硬门槛。画像与岗位要求只来自 JD，不读取候选人。

页面在源简历质量评级下、差距分析上增加要求解析。画像默认可见，详细岗位/候选人要求及原文依据按需展开。人才属性在候选人要求区展示，岗位说明引用该区，避免重复全文。使用现有浅色和字号体系，不引入新主题、字体或装饰动画。

旧结果缺少字段展示空态；不补调用、不改已有简历。未知版本或无效可选数据不能阻断页面。纯文本展示模型内容，不解释 HTML。

## 接入边界

- 完整 V5 定向测试路径：P02 的已有 `jobSuccessProfile` 增加可选 `candidatePortrait`，代码投影出公共契约；不是另开 Agent。普通 V5 默认 DSL 不因此自动切成未验收 Writer。
- 一句话画像只用于展示；P03 继续读取已校验的任务、条件及属性，不接收这份可选总结，避免展示性概括再影响岗位匹配。
- 实际 H5 分步路径：当前 `/match` 使用既有 JDParser + MatchingAgent，不是完整 V5 定向编排。JDParser 在原调用内输出同一公共契约；代码核对来源，匹配模型不得替换该 JD 解析。不能只改测试路径就声称已接入页面。
- 接口归一化、保存和历史恢复保持该字段；使用现有 process_result JSON，不增加数据库列或清洗旧数据。
- 可选展示异常本地省略，不加模型修复调用。核心原有 Schema 和业务安全规则不因此放宽。
- P02 输出已接近原限额，新增内容应简短并压缩重复。当前单阶段额度不增加，未证明实际 Token 成本不回归；需授权实测验证。
- 公共类型和画像契约属于当前 P01 缓存依赖。任何变化都重新 dry-run；旧缓存不能手工改哈希提升，新一轮冷缓存预算需另行说明。
