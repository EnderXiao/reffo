# V5 招聘质量标准与提示词修订

日期：2026-09-06。状态：招聘标准及兼容性提示词修订，尚未完成新版本真实质量验收。

## 一、好简历的本质

简历不是经历档案、关键词清单或自我评价，而是帮助招聘方判断“是否值得投入一次面试”的职业价值说明。它应降低对岗位适配、个人贡献和经历可信度的不确定性，而不是承诺候选人一定胜任或获得录用。

招聘阅读需要回答五个问题：

1. 此人适合承担什么工作，与当前岗位的哪几个核心问题相关？
2. 做过哪些相似或可迁移的工作，工作对象和复杂性是什么？
3. 在团队中具体承担了什么，而不仅是项目整体取得什么成绩？
4. 有什么行动、方法、交付或结果，可以形成有价值的面试问题？
5. 贡献、阶段、时间线和数字是否可信，是否存在必须进一步核实的边界？

### 不应混淆的概念

- 相关性不等于 JD 关键词密度：相同术语不能替代相似问题和实际能力。
- 具体不等于必须有数字：交付物、方法、复杂性和承担环节也可以构成具体内容。
- 结果导向不等于每条都填商业收益：研究验证、方案设计和初级实践不应被硬套成熟业务成绩。
- 强贡献不等于必须写“主导”：清楚说明参与环节，比虚高的所有权更有说服力。
- 完整不等于全部搬运：职业时间线需连贯，正文应有重点；合法的简短时间线不是空章节。
- 专业不等于术语堆砌：“赋能、闭环、协同推进”没有对象和实际动作时，不能替代具体表达。
- 可信不等于逐字复制：等义概括可以提高可读性；新增工具、方法、数字和成果仍需要本人真实材料。

评价职业阶段以明确职责和经历为依据。初级候选人看实践、执行与学习；资深候选人看判断、复杂问题和责任；管理岗位看决策与组织贡献。不能从年龄、性别、姓名推断能力，也不能以学校或公司名气替代工作证据。

## 二、如何对待信息稀疏的简历

先区分“表达简略”“经历有限”“材料冗杂”“目标岗位距离较大”，不统一要求长篇、固定条目数或完整 STAR。

材料简略时，把已知工作转译为招聘者能理解的职业含义；经历有限时突出真实实践、方法和交付；材料冗杂时挑选代表性事实；岗位跨度大时解释可迁移能力并保留真实缺口。

### 合理展开的边界

原文：`负责产品需求整理，和研发沟通。`

可采用的写作目标：`负责产品需求梳理与研发沟通，将业务诉求整理为清晰的功能需求，支持团队理解需求重点。`

这是对已有任务的专业化表达，不等于能够继续补写“独立输出 PRD、完成三次迭代上线、效率提升 30%”。行业常见做法只是可供用户确认的候选补充，不是本人经历。工作用途、预期价值也不能直接写成已经实现的效果。

可选补充优先问“你具体承担哪个环节、形成什么交付、解决什么问题”，不强迫用户确认每个普通措辞。不回答时仍可提供基于已知材料的基础版本。任何待确认建议应与简历正文分开，不把编辑口吻塞进投递稿。

## 三、对当前提示词的批评

| 当前问题 | 招聘视角的影响 | 本轮处理与边界 |
| --- | --- | --- |
| 证据数量和约束说明多，面试决策目标少 | 有材料，没有职业主线 | P03 增加问题、贡献、交付与面试价值导向 |
| 将没有数字、材料短与能力弱混淆 | 初级或表达简略的候选人被低估 | P03/P03R/P12 明确稀疏材料与职业阶段策略 |
| 泛化定位或直接贴 JD | 看不出个人辨识度，可能掩盖实际缺口 | P03 要求 1–3 条具体主线，区分直接能力与可迁移解释 |
| P06D 只能选择原文且必须覆盖全部必用证据 | 摘要复读、混合主题长句无法完全靠提示词解决 | 本轮仅改善合法槽位内的主题与长度分配，保留契约 |
| 对编辑说明的清理依赖有限代码规则 | 混合句中的核验口吻仍可能泄漏 | 不能要求 DSL 私自删除必用原子；需后续事实单元与展示层改造 |
| P12 把源证据当成品、把缺口当虚构 | 误报，修复方向失真 | 提示词要求成品短摘录、正确分类和核验不足说明 |

上一轮模型盲评为 V5 43.5、历史稿 62，只是当时 P12 r5 的结果；新 P12 r6 的措辞或评分变化不能直接当作产品质量提升。后续必须用同一评测标准同场比较冻结基线与新候选。

## 四、本轮已生效的提示词修改

- P03 r7：岗位问题优先，1–3 条职业主线；强调具体贡献、真实交付、职业阶段和稀疏材料利用；允许现有分析字段内的等义概括和可迁移解释，禁止把分析变成新事实。压缩 rationale，避免长篇重复。
- P03R r6：结构修复不得抹掉已经成立的职业定位与可迁移价值，也不得为了通过校验改成全量缺口。
- P06D r6：先查看全部合法槽位，再按同一业务问题组合行动与交付；同时考虑原文长度，不把余下证据一股脑塞进最后一个槽位。仍是软编排偏好，不得违反必用覆盖、scope 或文本契约。
- P12 r6：按招聘决策解释七个既有评分维度；事实指控先引用候选成品短摘录；区分证据与正文、核验不足与已证实造假、合法时间线与空章节、岗位缺口与写作缺陷。字符串数组及分数上限不变。

没有修改 P01/P01R、共用 trust prompt、Schema、生产编排、交付门禁、模型温度和 Token 上限，没有重新启用 P08/P09。P05 当前为代码计划，修改遗留 P05 文案不会改变默认选材行为，因此本轮没有通过修改非活动提示词冒充质量修复。

## 五、下一代写作提示词目标（设计稿，未接入运行时）

下面是恢复写作能力后的主编指令目标，**不是当前 P06D 可执行的替换文本**。必须先实现事实单元、允许编辑操作及相应校验，才可以注册新写作组件。

> 你是以招聘阅读与面试决策为目标的简历主编。基于源材料、目标岗位、允许的事实单元和章节计划，形成清楚、具体、有个人辨识度的职业叙事。
>
> 先识别材料充分度与明确的职业阶段，选择一到三条职业主线。用业务问题、个人行动、方法、交付与结果支持定位，不把职位名或 JD 关键词当成能力证明。
>
> 材料简略时，充分解释已有工作的职业含义和用途；没有数字时写清行动、方法或交付，不强行补结果。材料丰富时做取舍，不全量搬运。
>
> 每条正文围绕一个主题组织。摘要综合定位与代表性优势，不复读一条正文，不自封专家，不累计未被明示的年限。
>
> 在已获支持的编辑操作范围内，允许专业化改写、去非事实冗词、拆句与同主题重组。保留贡献、阶段、否定、数字、单位和归因边界。用途不等于已经实现的收益；常见工具、流程和方法不等于本人用过。
>
> 不写材料等级、核验记录和投递建议。若事实与说明混合，依照服务端提供的可用事实单元表达，不能自行删除可能改变意义的限定。合理猜测的具体经历仅作为独立补充建议，不进入投递正文。
>
> 优先形成自然、重点明确的可用简历，不为字数、条数、STAR 或量化密度填充内容。无需额外模型互审循环；输出只使用新写作契约明确允许的字段与操作。

这份目标指令仍需要实现层支撑。不能一面要求“自由润色”，一面使用“只能逐字复制”的校验器，也不能只验证数字与引用 ID 就宣称任意改写语义可靠。
