## 1. 修复结果

r18 的失败不只是模型误标：代码要求被引用句确实含未来信号，才能隔离其风险。模型将已批准句误标未来时，该条件不成立，风险继续影响前面的独立职责，导致“抽取保留、选材拒绝”。

r19 把“证据边界”和“风险判断是否正确”分开：

- 仍要求源块完整、唯一标注、引用精确匹配末尾完整句、前句明确且独立、无条件/撤回/指代依赖、容量与派生 ID 合法。
- 有限的局部状态识别现在同时接受计划/待定和已批准表达；识别的是可隔离的状态单元，不证明任职、上线或成果发生。没有岗位名、案例 ID、人员姓名或特定日期规则。
- 即使模型误标已批准句，也把独立职责与该句分开。职责保留逐字内容、source_qualified、原归因及属于该句的限定；被引用句保留原风险并 excluded，不能进入正文。
- 不根据“批准”清除整段风险，不恢复模型已 excluded 的事实，不绕过注入、隐私、冲突、不确定性、作用于整段的计划上下文。未知句型、缺引用或非完整引用仍沿用原处理。
- 补充前一句、这些工作、仅为模拟等依赖/撤回反例；前句本身有否认或撤回表达也不能被恢复为职责。

P01/P01R 升级 r19，强调风险定位不是整段裁决、状态和职责分离、qualifiers 不重复整块。根结构仍为 9 字段，不增加模型步骤、重试次数、事实容量、Token 预算或 Agent 门禁。非生产独立 P01 非思考配置不变，未切换生产默认。

这是有边界的局部处理，不是通用语义理解器。模型如果仍误标审批句，该句会暂时不能用于成品；本次解决的是独立职责被连带封锁，不以伪造审批事实或假定已任职弥补。
