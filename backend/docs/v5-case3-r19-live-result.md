## 2. 确切失败点

错误为 `P01_VALIDATION_FAILED`，第 1 片在一次 P01R 后仍有两条 `SOURCE_SCOPE_SECTION_MISMATCH`，并非接口故障、输出截断或“只有思考没有正文”。

实际保存的原始响应经零外呼回放可复现：

- 模型将开头 B0006–B0013 共 8 个未获对应经历 assignment 的文本块标为 result，并挂到后文经历。
- B0006–B0010、B0012–B0013 被挂至 B0014 对应 scope；该 scope 服务端成员实际只有 B0014–B0017。
- B0011 被挂至 B0021 对应 scope；该 scope 服务端成员实际只有 B0021–B0023。
- `normalizeResumeExtractionChunkCandidate` 只对有 assignment 的块覆盖 scope；没有 assignment 时保留模型 scope。这使模型冒用服务端 scope 的归属继续进入下游。
- 校验器随后发现这两条 scope 的实际成员越界，正确拒绝混写。P01R 未更正，仍重复相同越界分配。

归因：模型没有遵循概述材料不得自行挂到经历的指令；同时，代码对“无 assignment 的块冒用服务端 scope”缺少确定性归一化，仍依赖模型修复。不是源简历本身无效，也不是 r19 的句级风险隔离再次失效。

修复方向：代码明确区分服务端已分配的经历事实与未分配的概述/摘要材料，禁止后者冒用任一业务 scope，原文保留在非经历上下文供后续使用；关联真实经历需另有可验证依据。不能为了通过校验扩展经历成员集合或把摘要全部删除。先以本次主抽取和修复响应做本地回归，不反复全量抽样。
