# V5 结构性编辑：有边界的扩大验证

日期：2026-09-07。分支 `private/reffo-hsl`。既有未提交修改保留；本轮不提交、不推送、不部署。

## 目标与边界

解决候选人主线不清、代表贡献埋在职责中、板块重复三个问题；不是继续加事实门禁或追求 Case3 满分。客观岗位差距不作为写作失败，引用存在不等于语义完整，程序通过不等于招聘质量通过。

本轮采用独立、默认关闭的 `writingEditorialPolicy: document-editorial-v1`。原 r16 路径与输出结构不变；候选使用 r17 变体 `P06C-structural.md`。不开通 HTTP 参数或生产默认，不增加正常模型阶段，不恢复 P08/P09/P12，不提高 Writer 4,320 输出额度。

## 已实现

1. 全篇编辑摘要：引用两个已选代表实践，关联其岗位任务与正文位置；允许一个现有职责作为职业背景。只给已有证据关系，不由代码生成新的候选人能力结论。
2. 代表贡献：当一条职责内已有可写的具体行动/交付时，以该行动为段落核心，职责保留为可选背景。来源、经历归属、数字、阶段和参与边界不修改。无相关行动时保留职责，不要求补足完整 STAR。
3. 板块分工：摘要定位、工作贡献、项目/研究展开、技能方法分别承担不同阅读任务；新提示词重写为整篇编辑指导，不在 r16 上继续堆叠规则。
4. 兼容与预算：默认仍 r16，显式开启才 r17；同一响应 schema、输出额度、slot 数量。局部 facts 继续限制实际引用，不重新开放整池事实。

## 本地验证

- 909 项测试、4,520 断言、70 个文件通过，类型检查通过，diff 检查通过。
- 新测试覆盖：行动替代职责成为段落重点、职责仍可用、不把辅助语境或跨经历事实提升为贡献、源数据不可变、重复应用幂等、摘要依据至多两项实践加一项背景、稀疏材料不造职业身份、默认模式不变、源文不能切换变体、真实 workflow 只走一次 Writer。
- Case3 默认 r16 的 payload 与历史实际请求完全一致，system prompt 完全一致。
- r17 候选仍 19 个 slot，输出额度仍 4,320；本地估算输入从 10,430 到 9,579 Token，system 文本从 4,981 到 2,629 字符。只是同一估算器的结果，不是实际 API 账单或质量提升证明。
- 将已有 r16 实际响应放入新代码计划做零外呼兼容检查，代码通过，保留 warning。**没有生成 r17 新简历，不能称作 r17 真实生成成功。**

## 实测设计与停止条件

- 每个配对比较默认 r16 和显式候选 r17；Case3 原岗位复用已有 r16 实际成品，其余需要新基线。
- 同一人的 P01 结果在源/schema/实现一致并通过校验后复用。候选的 P02/P03 仅在与对应基线实际请求匹配时重放，保证写作比较不混入上游分析变化。
- 总封顶 42 次实际外呼、输入 450,000 / 输出 100,000 Token；每配对每模式最多一次 Writer。全部失败请求与未知用量保守结算纳入上限，不自动扩预算。
- 保留流程固有的有限结构修复额度；不给 P08/P09/P12 配额，不新增在线互审。失败样本保留，不能只汇报成功稿。
- 评估主线清晰度、代表贡献可读性、板块互补、重要信息保留及无依据扩写；对代码校验、实际生成和招聘质量分别记录。AI 辅助阅读不叫真实招聘人员盲评。
- 方向性判断重点看新增三位候选人：至少两位在主线/贡献/去重中有可说明的净改善，剩余样本无明显退化；Case3 同人多 JD 不出现身份或经历伪装。样本过小，不用此标准代替上线标准或宣称统计显著。
- 若主要仍是换词、事实遗漏转移或更高成本，停止这条补丁路径，报告无明确净收益。100 份真实黄金案例、30 份对抗输入、20 个同人多 JD 组和真实招聘人员评审等正式上线条件不变。

## 授权与首批终止记录

尝试启动扩大测试时，环境自动审批拒绝了命令：现有“扩大测试”授权未被认定为明确允许把新增主体的简历/JD 发送到 DeepSeek 这一具体第三方。进程未启动，本轮新增实际 API 调用为 0。

未绕过拒绝、未更换传输路径、未缩换样本暗中外发。随后用户针对上述六组简历与 JD、DeepSeek 非生产 API、42 次调用和 55 万 Token 上限明确回复“确认授权”，据此启动冻结基线。

首批第 16 次外呼在 S05 的 P02 请求处超时，评估控制器将整批置为 terminal。15 个已返回请求正常有正文；超时账单未知，按输入估算 8,336 / 输出上限 7,200 保守结算。没有将未知用量清零或恢复终止 journal。

用户随后明确要求“继续”。续批另存 journal，锁定原 journal 哈希并扣除所有保守结算，仅使用剩余 26 次、输入 280,850 / 输出 47,623 Token；复用经过验证的 P01 缓存，不重复已完成 Writer。隔夜继续使用新的两小时执行窗口，不声称原批端到端在两小时内完成。

**r17 的迁移收益未达到预设采纳条件，保持默认关闭；不把 r16 默认视为上线质量认证。** Case3 原岗位代表贡献更醒目，但摘要原始汉字由 72 增至 163、技能 101 增至 120；其他案例没有普遍净改善。S02 还出现源文毕业生被写成在读的错误。

扩大测试确定了优先级更高的问题：

1. S02/S05 的独立个人项目在 P01 前即被服务端归到前一个项目，Writer 继承错误 scope。需要单月项目标题的结构识别正反例。
2. 摘要数字规则将任意数字当跨经历累计；明确保留非个人承载边界的文本仍可能被拦。应校准规则语义，不引入付费 Judge。
3. S02 源文与 Writer 输入已包含 JD 所需 SQL，但输出遗漏；技能方法概括与必要工具信号应并存，毕业状态不可因 JD 条件改写。
4. S09 将“未体现某类经历”设为需要证据的 explicit_gap，空证据触发 P03 失败。缺少材料应与明确冲突分开。

本轮停止追加同配置模型重试；后续应先做上述零外呼回归，再恢复受控实测，不继续堆叠整篇编辑指令。
