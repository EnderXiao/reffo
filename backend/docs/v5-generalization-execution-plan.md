## 1. 固定产品与评审原则

目标：在已有材料支持范围内，让招聘者看清候选人的真实贡献与目标岗位重要任务之间的关系。材料充分度、实际匹配程度、表达质量分别判断；不要求优化后人人满分或进入面试。

- JD 分析：任务—成功条件—候选人属性—期望证据。六类属性是检查视角，不强制填满；必要、优先、推断和未知分开，允许不同胜任路径。
- 材料理解：保留完整工作对象、责任、行动、交付或结果及限定；有则保留，无则留空。普通无冲突自述可以使用，不逐条要求外部证明。
- 选材：按招聘判断选择代表贡献，而非关键词、数字数目或每段平均条数。重要性由独立标注判断，系统没选不自动等于候选人没能力。
- 写作：材料少时解释已有职业含义，材料多时合理取舍。应届实践、研究、销售运营、职能服务、管理等使用不同观察角度，不复制一套产品经理 STAR。
- 扩充：允许等义重写、目的解释、有依据的跨经历归纳；不能从行业惯例补出个人工具、流程、主导关系或业绩。用途不等于已实现收益。
- 结构：既有公开 Markdown/JSON 契约不变；无材料不强凑七个板块，不能靠删除关键内容通过交付。
- 成本：单向代码编排、有限并发和恢复、一次正文生成；不恢复 P08/P09 循环，不因风格或匹配分触发重写。

## 4. 首批实现

### 4.1 排版续接

之前只允许相邻 span 相差 1 个字符，空行或缩进会使本可闭合的原句变成不可选碎片。现在只对原规范文本证实的空白换行、相邻完整 block、词法可闭合的边界保存稀疏证明，再绑定到服务端构造的证据。

- 不使用固定 `gap <= N` 推测内容，也不使用填充空格重建文本证明原间隙。
- 制表、列表/表格、控制字符、非空白、跨来源/经历、局部引用、危险或冲突成员不因此放宽。
- 证明绑定原文、坐标、来源和归属；JSON/严格 Schema 往返后行为不变，不依赖 WeakMap 对象身份。
- 旧无证明数据保持旧的保守行为，不伪造或升级缓存。新依赖进入抽取指纹，后续真实测试需重新预检缓存状态。
- 证明仅本地消费，模型输入剔除服务端证明字段；不修改 P01 候选输出契约或模型额度。

### 4.2 信息去向报告

`acceptance/evidence-flow.ts` 与 `scripts/audit-v5-evidence-flow.ts` 提供零外呼本地观察：

1. 原文单元是否被完整抽取；
2. 证据路由允许怎样使用；
3. 是否出现在岗位匹配关系；
4. 是否进入选材计划；
5. 是否可由 Writer 正文槽位引用；
6. 是否出现在最终正文引用中。

没有执行/提供某阶段记录时为 null，不把未知算作失败或 100%。摘要引用不冒充正文覆盖，局部 Writer excerpt 不冒充完整源文单元；未经标注的未选材料只列去向，不自动判定质量缺陷。`firstUncoveredStage` 是首个观测到未覆盖的阶段，不是自动归因裁决。

引用覆盖不等于语义充分表达。报告明确 `semanticQualityAssessed=false`、`releaseAcceptanceAssessed=false`，没有质量分或放行布尔值。它不进入在线门禁，不调用 Writer，不改变计划。

报告只含 ID、坐标、分类、计数，不复制原简历/JD/成品正文、身份联系方式、匹配理由或自由文本评语。详细报告存放私有本地产物目录，不进入公开 API、日志或提交。

使用（backend 目录）：

```bash
bun run scripts/audit-v5-evidence-flow.ts --help
bun run scripts/audit-v5-evidence-flow.ts \
  --result <历史结果.json> --out <新的本地报告.json> \
  --resume-source <与历史输入完全一致的纯文本> \
  --jd-source <原始JD纯文本> --annotation <预先冻结的标注.json>
```

不带原文/标注仍可查看证据去向，但无法识别未抽取的源单元，也不会生成重要事实遗漏结论。历史 JobRequirementBundle 没有完整 JD hash；CLI 有 JD 时检查引用坐标和文本一致性，但不假装证明未引用部分与历史输入一致。`jdOriginalInputDigestVerified=false`，最终验收仍需冻结原始输入记录。新报告使用排他写入和 0600 权限，不覆盖旧报告。

### 4.4 通用动作与岗位任务选材

后续本地检查发现两类可复现的选材损失，已针对规则修复，而非加入 Case3 特例：

- 原有限动词表漏掉销售“洽谈”、财务“复核”、客服“受理”和英文 Audited/Processed 等源动作。路由复用 P01 的业务分类和 `sourceActionVerb`，要求动词确实位于原文、具有词边界与工作对象；只有这类源定位成立时，才跳过无句末标点职责/纯指标标签的启发式。标题、技能标签、背景、碎片、编辑说明、风险与原状态仍分别检查，不把 P01 标注当成免检通行证，也不新增行业动词表或模型调用。
- 定向选材为补 result/deliverable 类型，会替掉某核心岗位任务唯一证据。现在只在 targeted 模式检查替换前后任务覆盖：允许同任务替换或保留另一条等效证据，不允许仅为类型多样性删除已覆盖任务；不要求未知任务强行出现，也不改 legacy 选材。

路由行为版本记录为 `evidence-routing-v3`。额外回归区分“不增加成本”这类业务约束、“尚未上线的原型中”这类阶段场景与真正的动作否定，正向工作进入本地计划与 Writer 后仍保留原阶段词。这是受限的词法边界处理，不宣称识别所有复杂语法；陌生动作缺失可原文定位的 P01 动词标注时，仍可能需要真实样本揭示遗漏。

### 4.5 共享软篇幅预算

`writing-editorial-v2` 修复“Prompt 已取消固定篇幅、代码仍按每条 105 字压缩”的不一致：

- 篇幅需求取决于该槽位真正分配到的核心材料及相关补充材料；补充材料权重较低，无关/未选事实不占篇幅。
- 已有丰富材料可以获得更多展开空间；稀疏材料不因总额度充足就被要求填满。工作概览与重复项目详情使用不同重点，不能借此增加原文没有的行为。
- 槽位共同使用原 `outputLength` 软预算，给摘要、标题和已有教育/技能等信息预留空间；预算紧张时核心任务优先。中英混合/跨语言材料采用输出单位估算，不用英文字母数冒充英文词数。
- 所有系数和 `lengthHint.target/max` 都是待真实样本校准的编辑建议，不是最佳字数、质量得分或新增硬门禁；不改变槽位、证据、数字限定、P06C Token 额度，不触发重写。未启用 targeted 的历史 Writer 不收到该编辑协议。
