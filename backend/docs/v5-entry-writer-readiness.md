## 已实施

### 1. 提示词与材料组织

个人优势、工作、项目、技能、教育、证书按不同招聘判断组织；研究与奖项另有表达分工。项目围绕问题/需求、方案判断与边界、本人动作和产物、结果或真实交付状态展开。四个维度不是四条必填项。

提示词明确允许整理逻辑、解释用途、归纳有实践依据的能力、专业化改写。普通信息缺口不要求在正文反复写审计式说明，重要参与程度、阶段和事实限定仍保留。新增稀疏材料对照例及独立输出指令，避免旧通用“缺证据用 null”与非空正文契约冲突。

`writing/entries.ts` 将同一工作/项目的槽位合成经历材料包，恢复因单槽分配而丢失的已选材料，并补入同一已验证 scope 内的无风险上下文。背景不再必须带专门标签或句号；不跨 scope 合并，也不将补充背景升级为必写成果。

先完成经历和角色组织，再分配软篇幅；篇幅不再继承原概览槽位的压缩系数。模型先写业务正文，再归纳摘要与技能，最终展示顺序仍由服务端决定。

### 2. 内部协议与兼容编译

输出为 `entries[{entryId, paragraphs[{role, text, evidenceIds}]}]`。业务经历允许可变段落；单一长原文可以支持同一经历的互补段落。非业务条目保留精炼单段，外部 Markdown/JSON 框架不变。

未知/重复/遗漏经历、非法引用、跨 scope、明确数字或事实边界变更继续由代码检查。不再把同一经历的重复来源引用等同于重复正文，并防止旧归一化器删除后续段落。段落数量下限在新模式中降为质量提示；缺少某个信息维度不触发模型重跑。

原选材计划不覆写。新结果内部的 `entryWriting` 保存渲染计划和服务器生成的段落路径，用于原样复核；重复引用许可不能由模型或 HTTP 请求指定。离线重验新结果时须使用该视图，不能再拿旧固定槽位条数验证。公开 MVP 响应不暴露此内部记录。

### 3. 调度、正文流与调用核算

- P01 改为有界 worker pool，空闲后启动下一片；保持原并发上限、稳定索引、全部 primary 屏障、源序修复和有序合并。错误时等待已启动任务收敛再退出。
- DeepSeek Provider 支持内容流与末尾 usage 汇总，只传递正文 delta，不转发或保存思考正文。
- 完整经历 JSON 对象经局部校验后进入生成中预览；最终仍执行整篇编译和校验。EOF 缺少终止帧、截断、空正文不伪装成功。
- 提供单次运行内的事件序号、预览去重及游标回放；观察者断线/异常不启动第二次生成。预览不是正式成品，失败会发终态失败事件。
- 去除 Provider 的空正文隐式重试。结构化空正文仍返回实际 usage，由上层记录费用后诊断。新 Writer 在 fallback 包装层也限制一次尝试、一个模型。
- 非生产 runner 仅打印不含正文的进度计数，不把完整简历或思考内容送入通用日志。
