- “计划证据 ID 未引用”只是诊断线索，不能直接计为真实内容遗漏；同义表达、同范围详情替代、计划后续调整要分别核对。

## 2. 已完成的可复核定位

### 2.1 日活规模遗漏：写作计划将后半句列为可取舍

源证据完整提取，也已选入计划、实际 Writer 槽位和输出引用。源句的前半句是三项功能上线，后半句是产品日活规模。

`writing/facts.ts` 当前取第一个分号/句号前的片段作为 focusText，并仅用该片段生成结果/交付的 requiredNumbers。因此该例 3 项是必保留数字，200K 是 protectedNumbers 中可取舍的信息。Writer 正常保留前者、省略后者，代码已产生质量 warning。

结论：不是 P01 提取丢失，也不是 Writer 没收到数字。**按句子位置判断信息重要性存在可迁移的局限**，但不能把“所有后半句数字都强制保留”当作修复。该数字是否对本岗重要仍待独立评审。

### 2.2 五个计划内未引用 ID：没有一个进入实际 Writer 槽位

- 两条业务事实在初始规划和初始蓝图存在，在写作计划的分组、相关性与数量限制处理中没有进入最终槽位；并非模型拿到后漏写。
- 三条原技能进入旧技能槽位后，被方法技能主题替换。它们仍留在内部事实表，但没有放入实际发给模型的 slot-local facts。
- 其中“目标管理”概括在项目详情有相近覆盖，“跨部门交付”在技能和经历有实践表达；不能把五个未引用 ID 全算成五项能力消失。另一个具体流程设计动作是否值得替换进正文，需要按 JD 和现有篇幅比较。

结论：需要审查规划与最终写作计划之间的信息去向，而非增加 Writer 的“不得遗漏全部计划证据”要求。

### 2.3 摘要与技能重复：同一套排名分别分配，没有跨板块互补选择

摘要的两个主题锚点，与技能前两条完全相同；这些实践同时有业务正文槽位。当前两次主题选择主要使用相同相关性排序和各自内部去重，不以另一板块已承担的信息为约束。

复用同一证据本身是合法的：摘要定位、技能方法、正文证明可以共用来源。当前问题是成品重复事件细节，不能简单禁止共享 ID，否则会惩罚材料少的用户。

结论：属于信息分工与表达问题，非事实错误。优先通过同输入对照评审确认改善空间，不增在线语义门禁。

### 2.4 工作首条偏长：代码已给主次，模型仍合并全部可选职责

实际输入将系统分析行动设为唯一核心，给出 contribution 角色和 74/94 的长度参考，同时仍提供两条职责作为可选材料。模型将三条全部写入，输出 146 个汉字。

结论：不是没有提供主次提示。需要考虑可选材料是否过量及信息分配是否合理；单纯再写一次“简洁”没有足够依据。该问题属于可读性问题，不自动判事实失败，也不添加超长硬阻断。

### 2.5 优先风险：任务关联在写作指引中被摊平成胜任指向

实际 P03 对“模型效果评估”任务给 weak_signal，并明确说明缺少相应研发评估实践；双周发布的证据不在该任务 link 中。

但 `writing/plan.ts` 将所有可用于选材的 link 所关联 target.taskIds 合并成无状态的 task 集合。一个通用协作属性关联多个任务，以及一个只支持部分内容的复合要求，都会把“模型效果评估”带进双周发布主题。`writing/themes.ts` 继续把这些 ID 写入 targetTaskIds，未携带是直接任务证据、仅属性关联，还是复合任务部分支持的区别。

这不能解释为 P03 已直接认证候选人具备模型评估经验。本轮成品也没有作出该声称；原始 links/editorialIntents 仍保留部分限制，属于**内部编辑信号互相矛盾、可能误导后续生成的风险**。

另有一个实际 P03 复合属性：状态为 direct，但 difference 同时承认没有“大模型应用产品逻辑”的明确证据。它违反当前 P03 对复合目标部分支持的提示要求，属于需要处理的匹配状态一致性问题，不应由 Writer 猜测如何解决。

## 4. 下一修复批次的有限范围

建议下一批只处理 2.5 的内部匹配信号一致性，先补失败回归再实施，不同时改摘要长度、技能文风和数字保留策略：

3. 验证同一段普通发布经历不能认证模型评估，但真正提供模型评估实践的源材料必须正常保留；直接、可迁移和局部支持都要有正反例。
4. 复合目标语义边界代码不能全面判断。先检查是否能复用已有独立任务映射做一致性诊断；诊断不一律变成生成门禁，不新增在线 Judge、P03/P08 互审或全局反复改写。
