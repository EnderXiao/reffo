## 实现边界

- `--artifact-mode writer_v1 --job-targeted` 为非生产显式选项；既有默认路径未切换。
- 新内部契约为 `job-success-profile-v1`、`job-fit-map-v1`；外部 MVP 顶层字段及简历栏目不变，六类属性不形成六个新栏目。
- P02 只读取 JD，不根据候选人反向修改岗位要求。P03 等待完整 P01 与 P02，P01 既有稳定分片排序和检查点机制保留。
- 岗位判断与个人证据使用不同引用空间；代码拒绝把岗位目标 ID 当作个人事实引用。未知项不自动等同不合格。
- 代码把可选主线的引用合法性与胜任支持分开：原生或代码降级的弱信号、未知等主线可本地省略，不因此请求模型修复。非法引用等硬错误仍按既有有界规则处理。局部实践的选材价值独立于匹配状态，保留真实实践不等于认证完整岗位要求。
- 选材按核心任务及具体行动/交付支持排序，六类属性采用最大相关权重而非累加，不靠多个同义标签刷高同一事实。
- Writer 只调用一次；P02/P03 原有最多一次结构修复保留。普通质量 warning 不启动互审或正文重写。
- P12 增加原始 JD 审计输入，避免只根据 P02 的分析结果评成品；七维权重不变。P12 仍为独立离线辅助评测，未在本轮调用，也不能代替真实招聘人员。
- 代码可以验证来源引用、数字等确定条件，不能证明所有语义判断正确。招聘质量和画像准确性必须由独立材料及人工评审验证。
