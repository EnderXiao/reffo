# V5 entry r5：修正任职补全引发的结构退化

日期：2026-09-08。

## 根因

r4 在选材目标中扣除了固定任职范围说明，却没有在辅助内容剩余额度中记账，导致重复分配。排版又将原始四段工作正文压到一段以满足 18 条限制。保留所有字句没有保留阅读结构，上轮验收也缺少对比回归指标。

## 修正

- 固定范围说明只计一次预算，辅助内容不重复使用其额度。
- `entry-layout-v2` 在 entry 模式区分选材目标和展示硬上限。展示余量不超过六条，本例 18 → 24；总长度、项目数量和事实校验不放宽。
- 超出展示硬上限时，只合并同经历内短小、角色兼容的段落。禁止问题与方案、职责与贡献的机械拼接；拼接后中文最多 140 字符、英文最多 80 词。不能安全排下的情况仍由代码给出预算错误，不触发模型互审循环。
- P06C entry 版本为 r5，提供按任职重要程度分段、段落长度与结构保护指令；输出 Token 上限仍为 4,320。

## 验证

Case3 使用 r4 已有真实响应，0 次新外部调用。先保持旧计划隔离排版，再将完全兼容的经历与引用投影到最新计划。原响应不改写，投影仅涉及 entryId 与当前计划未选项。不是 r5 真实 API 成功运行。

最新计划重编译后：当前任职 1 → 4 段，Xmind 1 → 2 段，两个项目各 2 → 3 段，研究 2 → 3 段；最长工作段落 450 → 132 字符；补全的两段任职仍在。总正文汉字 1,541 → 1,527，减少项来自不再选入语言能力，业务句子未删除。

1,000 项后端测试通过，TypeScript 与 diff 空白检查通过。新增回归覆盖双重预算、结构保留、有限余量、不同语言、段落角色和长度上限。
