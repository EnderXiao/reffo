## 一、结论

v4.2.1 已把选中的 5 个 v4.1 弱项案例从 **0/5 可交付**提升到 **5/5 可交付**，定向样本交付率为 **100%**，事实确定性护栏失败为 **0**。

另有 1 次 Flash 评审响应未返回可解析的候选分数，记为 `unknown`，没有纳入平均分；其余 19 次有效评分均保留。

上述结论只适用于本轮刻意挑选的 5 个 v4.1 弱项，不能替代 30 个案例的重新全量回归，也不应表述为总体 100% 通过。

## 三、输出范围边界

v4.2 把两个容易混淆的维度彻底拆开：

1. **简历输出质量**
   - 事实是否忠实；
   - 是否准确对齐已有证据；
   - 顶部三分之一是否有说服力；
   - ATS、可读性、非模板化和面试可防守性是否合格。
2. **申请包与候选人证据完整度**
   - 作品集；
   - SQL 测试或高级 SQL 证明；
   - 证书原件；
   - 英文能力证明；
   - 其他需要候选人在产品外补交或现场验证的材料。

第二类缺口只进入 `application_package_gaps`、`additional_application_materials` 或 `application_readiness`，不得进入 `delivery_blockers`，也不得自动让一份事实安全、表达合格的简历不达标。

因此：

- Apple UX Designer 的作品集要求仍会被识别和提醒，但不计入简历输出质量失败；
- Amazon 高级财务分析岗位的高级 SQL 证明仍会被识别和提醒，但不计入简历输出质量失败；
- 英文能力、跨国公司背景等候选人资格缺口仍会诚实保留，但与提示词是否生成了一份高质量简历分开评价。

## 四、主要优化

### 1. 范围隔离

- 新增统一 `OUTPUT_SCOPE_CONTRACT`。
- JD、匹配、生成、内部 Judge 和盲评使用同一边界。
- `deliverable` 改为等同于 `resume_quality_passed`，不再等同于“候选人满足所有申请条件”。

### 2. 更激进的岗位对齐，但不升级事实

- 允许大幅重排内容和压缩无关经历。
- 顶部三分之一必须回答候选人是谁、最相关的 2–3 个证据支柱、能解决什么目标问题。
- 只允许使用已绑定 `evidence_id` 的候选人陈述。
- 公司体量、负责人经历、招聘风格和员工口碑只用于分析策略，不写进候选人简历。

### 3. 数字事实原子化

- 数字、单位、归属、时间和限定词视为不可拆分的事实原子。
- “约、近、超过、至少、最多、不足、逾”等必须保留。
- 禁止根据任职日期自行计算“X 年经验”。
- 禁止把“约 2180 万”重新概括成“超 2000 万”。
- 确定性护栏新增“数字存在但限定词被删除”的检测。

### 4. 限制语义升级

“驱动决策、赋能、保障效率、管理期望、主导、全流程、决策支持”等结果、所有权或范围升级词，只有源证据明确支持同等语义时才可使用；否则只能保留已证实的动作、对象和指标。

### 5. 修订动作可验收

- Judge 的每条 `revision_action` 都是强制验收条件。
- 给出明确替换文案时必须原样采用，不能再次润色成更强语义。
- 修订输出增加 `revision_verification`，逐条记录动作、目标、执行状态与最终文本。
- 证据为空时只能删除、降级、保留缺口或交给用户核验。

### 6. 修订版本自动回滚

运行器保存初稿及每轮修订快照，按以下顺序选择最佳版本：

1. 确定性事实护栏通过；
2. Judge 判定可交付；
3. 简历质量通过；
4. 总分更高。

若新修订比旧版本差，会自动恢复旧版本，不再盲目采用最后一次修订。候选 ID 也改为由运行器最终覆盖，避免模型返回的旧 ID 干扰版本选择。

## 五、定向样本选择

从 v4.1 的 30 个案例中，只选择满足以下任一条件的案例：

- v4.1 相对旧版的盲评绝对提升小于 10 分；
- 资格判断为 `pass`，但最终简历仍不可交付。

共选出 5 个案例：

1. `resume_01:resume_01_job_03`
2. `resume_06:resume_06_job_03`（Apple UX Designer）
3. `resume_07:resume_07_job_02`（盒马 NB 店长）
4. `resume_08:resume_08_job_03`
5. `resume_09:resume_09_job_03`（Amazon）

v4.2.0 首轮通过 3 个。随后只复测剩余 2 个失败案例，没有重跑已通过的 3 个案例。

## 八、联网研究说明

v4.2 提示词仍保留并强化公开网络研究能力，研究范围包括：

- 公司体量、性质和业务阶段；
- 目标岗位负责人、直属上级或最接近的公开领导链；
- 负责人或直属上级的公开工作经历；
- 招聘偏好与面试风格；
- 在职员工公开口碑和重复出现的主题。

研究结论必须区分 `verified / inferred / unknown`，保存 URL、标题、发布日期或访问日期，并禁止把匿名口碑当成公司事实。

由于用户要求节约 Token，本轮定向测试直接复用 v4.1 已生成的公开研究包，没有再次搜索网络。研究状态为 `partial` 时会保留不确定性，不会补造信息。

## 十一、生产晋级

人工评审通过后，生产提示词已统一切换为：

- 版本：`4.2.1`
- 变体：`scope-aware-v4.2`
- 核心事实、输出范围、外部情报、数字限定词和申请材料边界：直接复用已测试的 `V42_SHARED_CONTRACT`
- 生产 JSON/Markdown 响应结构：保持兼容，不要求前端同步迁移
- 运行追踪版本：`v4.2:scope-aware-v4.2`

旧客户端传入 `v1`、`v2` 或 `final-v3` 时，服务端仍会统一解析到生产 v4.2.1；接口同时接受显式 `scope-aware-v4.2` 标识。

## 十二、限制与下一步门槛

本轮采用弱项定向回归，证明 v4.2 修复了已知失败模式，但没有重新验证全部 30 个案例。因此：

- 可以判定 v4.2 已达到人工评审和生产晋级门槛；
- 不能据此宣称全量总体通过率已经达到 90% 或 100%；
- 接入生产提示词前，建议由人工先审核 5 个 v4.2 页面，重点检查事实忠实、顶部说服力和是否仍有隐性语义升级；
- 人工通过后，再决定是否做一次小规模独立留出集测试，而不是立即重新跑全部 30 个案例。
