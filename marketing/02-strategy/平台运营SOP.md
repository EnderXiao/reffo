# Reffo 平台运营 SOP

> 版本：V1.0（2026-08-16）  
> 适用范围：中国大陆社交媒体；小红书为主，Bilibili、微信公众号/视频号、抖音、知乎为辅。  
> 事实依据：`marketing/01-product-analysis/feature-evidence-table.md`  
> 原则：先核实产品事实，再制作内容；先保护用户隐私，再讨论传播效果；每周复盘，规则有变化时及时更新本 SOP。

## 1. 角色与责任

| 角色 | 决策/执行责任 | 最晚响应 |
|---|---|---:|
| 运营负责人 | 月度主题、周排期、发布、互动、复盘和停发决定 | 工作日 4 小时 |
| 产品营销 | 定位、卖点、竞品、产品证据和发布口径 | 工作日 1 天 |
| 文案/研究 | 选题、脚本、搜索词、来源和引用核实 | 发布前 1 天 |
| 设计/视频 | 后续视觉、真实录屏、字幕、可编辑源文件和素材来源 | 按排期 |
| 产品/研发 | 功能状态、演示环境、埋点、错误和数据处理确认 | P0 问题 4 小时 |
| 用户研究/客服 | 种子用户、访谈、私信、授权和投诉 | 工作日 4 小时 |
| 法务/合规 | 隐私、广告、活动、达人合作、AI 标识和高风险用语 | 高风险内容发布前 |
| 数据负责人 | 平台和产品数据录入、口径维护、周/月报 | 每周一 12:00 前 |

小团队可以兼任，但以下审批不能由同一人闭环：真实用户案例、效果数字、付费活动、隐私政策、危机回应。

## 2. 内容生产总流程

`需求池 → 选题评分 → 产品证据核验 → 内容 Brief → 文案/脚本 → 隐私与合规审查 → 真实素材制作 → 发布前 QA → 发布 → 30 分钟/24 小时/72 小时跟踪 → 周复盘 → 归档`

### 2.1 每周节奏

| 时间 | 动作 | 输出 |
|---|---|---|
| 周一上午 | 上周数据与用户问题复盘 | 周报、胜出/停止/继续测试清单 |
| 周一下午 | 站内搜索词、热门内容和竞品快照 | 趋势记录、来源链接、检索日期 |
| 周二 | 确定下周 6 个小红书主题和跨平台复用项 | 内容 Brief |
| 周三—周四 | 文案、录屏、设计、审核 | 待发布成品和源文件 |
| 周五 | 下周排期终审；补齐证据/授权 | 发布包 |
| 每日 | 发布、评论、私信、线索与异常处理 | 平台台账、用户台账 |
| 周日/周一 | 72 小时数据补录和素材归档 | 数据看板 |

首月使用 `marketing/04-content-calendar/30天内容排期.xlsx` 作为唯一排期源。临时插入热点时必须新建行，不直接覆盖原计划，以便复盘计划与实际差异。

## 3. 选题入池与评分

### 3.1 入池条件

选题至少满足两项：

- 对应明确人群和真实求职场景；
- 能回答一个可搜索的问题；
- 有实际产品页面、源码或授权案例支撑；
- 能给用户一项立即可执行的检查/修改动作；
- 能测试定位、人群、钩子、形式或转化链路中的一个假设。

### 3.2 评分公式

每项 1—5 分：

- 用户需求强度 30%；
- 产品相关度 25%；
- 可视化程度 20%；
- 搜索/时效价值 15%；
- 制作成本反向分 10%。

`优先级分 = 需求×30% + 产品相关×25% + 可视化×20% + 搜索时效×15% + 成本反向×10%`

任一高风险项存在且没有解决方案，选题直接进入“阻塞”，不因高分发布。

### 3.3 趋势调研

每周在小红书站内分别搜索：

- 核心词：AI 简历、简历优化、一岗一简历、JD 分析；
- 人群词：应届生简历、转行简历、跳槽简历、实习简历；
- 岗位词：产品经理简历、运营简历、程序员简历、数据分析简历、设计师简历；
- 阶段词：秋招、春招、实习、补录、面试准备。

每个关键词记录前 20 条公开结果中的标题结构、发布时间、形式、用户问题、评论需求和商业内容比例。不得采集用户简历、联系方式或私密信息。趋势表只记录公开、必要的汇总，不保存无关个人数据。

公开搜索或第三方工具无法验证时，标为“待站内人工复核”，不得写成平台结论。

## 4. 产品证据核验

### 4.1 核验顺序

1. 在 `feature-evidence-table.md` 查询功能 ID 和状态。
2. A 级能力优先使用实际 H5 录屏再次验证。
3. B 级能力只能做源码/机制说明，不伪装为现有 UI。
4. C 级能力必须标明依赖条件，例如 OCR、登录、设备视觉等级。
5. D/N 级能力不得写成已上线。
6. 记录核验人、日期、版本、页面和素材文件。

### 4.2 常用安全证据

| 卖点 | 证据 ID | 素材要求 |
|---|---|---|
| 一个岗位一份简历 | F-01 | 首页实际卡片堆录屏 |
| 源简历 + JD 三段结果 | F-02、F-06、F-10、F-13、F-16 | 实际创建页和结果页录屏 |
| 证据优先重排 | F-11、F-12 | 源码机制示意或授权文本案例，不伪造 UI |
| 可编辑和下载 Markdown | F-13—F-15 | 实际编辑和下载录屏，写清格式 |
| 面试准备 | F-16—F-18 | 实际页面；注明为建议 |
| 岗位历史卡片 | F-19—F-20 | 实际首页/完成页录屏 |
| AI 人工复核提示 | F-30 | 所有结果素材保留提示 |

高频红线：N-01 分享、N-02 Word 解析、N-03 Word/PDF 精排下载、N-04 自动投递、N-06 ATS 保证、N-07 求职结果保证、N-09 零幻觉、N-11 全平台稳定、N-14 完善隐私体系。

## 5. 内容 Brief 模板

每条内容必须包含：

- 内容 ID；
- 平台与形式；
- 目标用户与使用场景；
- 要回答的唯一问题；
- 一句话结论；
- 标题/封面钩子 A、B；
- 内容结构；
- 产品证据 ID 和页面/源码；
- 需要的真实截图、录屏、文本案例；
- CTA；
- AI/隐私/结果风险；
- 信息来源、页面日期、检索日期；
- 负责人、审核人、发布时间；
- 72 小时主指标。

标题不先承诺结果。推荐先写场景或任务，如“同一段实习，投产品和运营时怎样换重点”，避免“这样写 Offer 拿到手软”。

## 6. 文案与脚本规范

### 6.1 小红书图文结构

建议 6—9 页：

1. 场景 + 明确问题；
2. 误区或判断框架；
3—6. JD、证据、修改动作和理由；
7. 实际产品步骤或结果；
8. 人工核验清单；
9. 非诱导 CTA 和 AI 提示。

正文结构：先给结论，再解释依据；每段尽量只表达一个动作；关键词自然出现，不做重复堆砌。

### 6.2 短视频结构

15—30 秒版本：

- 0—3 秒：具体场景，不用夸张承诺；
- 3—8 秒：展示源简历和目标 JD；
- 8—20 秒：真实 H5 步骤/差距/编辑；
- 20—26 秒：展示岗位卡片或核验动作；
- 26—30 秒：AI 核验提示 + 合规 CTA。

3—8 分钟版本：场景 → 原始材料 → JD 判断 → 修改依据 → Reffo 实际流程 → 用户人工修改 → 产品边界。

禁止剪辑“恭喜你”完成页暗示已经获得岗位；必须同屏保留“简历已经准备就绪”语境。

### 6.3 CTA 规范

推荐：

- “保存这份检查顺序，改下一份岗位时逐项核对。”
- “主页置顶有完整真实流程和使用边界。”
- “如果你正在同时准备多个岗位，可以在站内说明岗位和当前材料阶段。”
- “AI 初稿只是一版，请在提交前核对姓名、时间、数字和经历。”

禁用：

- “评论 1 发模板”；
- “点赞收藏后私信领取”；
- “加 V/主页有微/扫码咨询”；
- 虚假按钮、赠品换互动和隐晦站外导流。

## 7. 素材与视觉源文件管理

### 7.1 素材类型

- A：实际 H5 截图/录屏；
- B：源码支持的机制示意，必须标“机制示意”；
- C：授权、脱敏的真实用户文本案例；
- D：完全虚构的演示简历/JD；
- E：AI 生成人物、场景和背景；
- F：平台/竞品公开页面截图，仅作研究或在合理引用范围内使用。

AI 图片不得伪造 Reffo UI、按钮、价格、Logo 或中文界面。中文标题、Logo、价格和按钮必须用可编辑方式精确排版。

### 7.2 文件命名

`日期_平台_内容ID_主题_版本_状态.ext`

示例：`20260820_XHS_D04_JD三类证据_v03_approved.mp4`

源文件和导出文件分离：

- 可编辑源文件：`marketing/06-posters/source/` 或后续确认目录；
- 视频源文件：`marketing/08-video/source/`；
- 成品：对应 exports 目录；
- 字体与素材来源清单：和每批成品同目录保存；
- 临时截图、日志和测试文件不混入正式交付。

当前阶段不制作视觉物料，`选题与素材库.xlsx` 中只建立需求和状态。

## 8. 隐私、授权与 AI 检查

### 8.1 个人信息检查

发布前逐项检查：姓名、头像、电话、邮箱、微信、地址、证件、学校学号、公司内部信息、项目客户、薪资、未公开岗位、文件路径、浏览器账号和通知。

默认使用虚构样例。必须使用真实用户材料时：

1. 获得书面授权；
2. 记录用途、平台、期限、是否投放和撤回方式；
3. 由两人独立脱敏复核；
4. 只保留内容结论所必需的信息；
5. 发布后保留撤回和删除能力。

### 8.2 AI 标识

- AI 生成/深度合成内容按当时法规和平台功能使用显式/隐式标识；
- 不移除工具或平台添加的 AI 元数据/水印；
- 展示产品生成结果时保留醒目的人工核验提示；
- 文案由 AI 起草后仍需人工事实审核；
- 真实产品 UI 与 AI 场景画面在素材台账中分别标记。

### 8.3 用户案例授权字段

授权编号、用户代号、授权时间、素材范围、使用平台、使用期限、是否商业投放、是否可二次剪辑、是否匿名、撤回联系方式、原始文件位置、脱敏文件位置、审核人、撤回/到期状态。

## 9. 发布前 QA 与审批

### 9.1 四级风险

| 级别 | 示例 | 审批 |
|---|---|---|
| L1 | 通用方法、虚构样例、无产品承诺 | 运营 + 文案互审 |
| L2 | 真实产品录屏、评分、OCR、模型机制 | 运营 + 产品营销/产品 |
| L3 | 用户案例、竞品对比、付费权益、达人合作、活动 | 运营 + 产品 + 合规/法务 |
| L4 | 求职结果、提升率、投诉回应、数据泄露、监管问题 | 暂停发布；负责人 + 法务 + 管理层决定 |

### 9.2 发布检查表

- [ ] 产品卖点有证据 ID，状态与文案一致。
- [ ] 没有出现未上线能力或把规划写成现实。
- [ ] 标题、封面和正文没有结果保证、绝对化或焦虑营销。
- [ ] 真实用户素材有授权且双人脱敏。
- [ ] 真实 UI 来自当前运行截图/录屏。
- [ ] AI 画面没有伪造产品 UI，AI 标识符合要求。
- [ ] 产品内评分未解释为 ATS/招聘方评分或录用概率。
- [ ] 格式口径准确：当前主要是 Markdown，不写 Word/PDF。
- [ ] 没有联系方式、二维码、站外导流或诱导互动。
- [ ] 活动规则、时间、奖励和条件完整。
- [ ] 所有数字、数据和引用有来源、日期和原始链接。
- [ ] 字体、图片、音乐和第三方截图的许可可追踪。
- [ ] 字幕无错别字，画面无敏感通知、账号或文件路径。
- [ ] CTA、落地页和平台组件已实际测试。
- [ ] AI 结果人工核验提示清晰可读。

未全部通过时不得发布。

## 10. 小红书发布 SOP

### 10.1 账号与资料

- 账号名、头像和简介与认证主体/品牌一致；
- 简介不放联系方式、网址、邮箱、二维码或暗语；
- 置顶保持“产品是什么、如何使用、边界与隐私”三类；
- 企业专业号、广告账户和行业资质在运营前按最新规则确认；
- 每月检查账号健康和规则更新。

### 10.2 发布步骤

1. 从已审批发布包复制最终标题、正文、话题和封面。
2. 检查商业合作/AI 内容等平台标识选项。
3. 选择 3—6 个高度相关话题，不堆不相关热词。
4. 预览封面截断、字幕、安全区和移动端可读性。
5. 发布后记录笔记链接、发布时间、内容 ID 和版本。
6. 30 分钟内检查审核状态、错字、评论误解和入口可用性。
7. 24/72 小时录入数据；不为“重发”随意删除原内容。

### 10.3 评论处理

按四类回复：

- 方法问题：给出具体判断步骤，不把评论区变成销售话术。
- 产品问题：如实说明当前能力、格式和限制；未知内容先核实。
- 隐私/AI 质疑：解释数据路径和核验边界，不回避，不索取公开简历。
- 投诉/错误：确认收到，转私密、安全渠道处理，公开区不重复个人信息。

禁止与用户争辩、贬低竞品、伪装普通用户推荐、复制机械话术刷屏。

### 10.4 私信和线索

私信只收集完成服务所必需的信息。首轮建议字段：求职阶段、目标岗位类别、当前简历格式、是否有目标 JD、希望解决的问题。不要在小红书私信要求发送身份证、完整联系方式或与体验无关的敏感信息。

用户准备上传简历时，引导其进入经过审核的产品页面并阅读隐私说明，而不是在社交平台聊天窗口传完整简历。

有效线索定义：明确目标岗位/场景，愿意在合规产品入口完成体验，不包括泛问价、机器人、重复或无关咨询。

## 11. 其他平台发布 SOP

### 11.1 Bilibili

- 用胜出的小红书主题扩成完整案例，增加判断依据和产品边界；
- 标题可搜索，不使用“必过”“保姆级上岸”式保证；
- 简介和评论区导流遵守 B 站当时规则；
- 章节、字幕、简介都注明样例/授权状态和 AI 核验提醒；
- 记录完播、平均观看、搜索来源和评论问题。

### 11.2 微信公众号/视频号

- 只承接用户主动关注后的持续教育、版本更新和服务通知；
- 订阅、营销和即时通信消息遵循用户同意与拒绝机制；
- 长文引用外部规则和数据时注明日期与链接；
- 视频号复用需重做封面、字幕和时长，不原样搬运水印视频。

### 11.3 抖音

- 前 3 秒使用任务/场景，不使用结果保证；
- 真实界面出现时保留品牌和 AI 提示；
- 根据最新平台规则使用 AI 内容标识；
- 重点看 3 秒留存、完播和主页访问，不以单条爆量代替激活。

### 11.4 知乎

- 以完整回答为主，不在回答前半段硬植入产品；
- 对“AI 简历是否有用”等问题同时写能力与限制；
- 竞品比较使用公开功能事实和访问日期，不下效果结论；
- 更新过期规则和产品状态。

## 12. 数据记录与复盘

### 12.1 数据源

- 平台原生数据：曝光、阅读、互动、主页访问、关注、搜索来源；
- 线索台账：有效私信、表单、体验资格；
- 产品埋点：获客来源、源简历建立、JD 分析、生成、编辑、下载、保存、第二岗位；
- 支付：订单、收入、退款；
- 用户研究：问题、修改量、满意/不满意原因、授权。

平台口径变化时保留原字段和新字段映射，不把不同口径直接拼接。

### 12.2 复盘输出

周报必须回答：

1. 哪 3 条内容产生了最高价值互动和激活？
2. 哪 3 条内容低于中位数，原因是选题、钩子、形式、证据还是承接？
3. 用户最常问的 5 个问题是什么？
4. 哪些评论暴露产品误解、隐私顾虑或功能缺口？
5. 下周继续、停止和新增测试各是什么？
6. 是否出现投诉、审核、版权、隐私或 AI 标识事件？

月报增加：完整漏斗、渠道 CAC、D7/D30 第二岗位留存、付费/退款、UGC 授权、预算消耗和产品需求优先级。

数据工作簿：`marketing/09-performance/数据指标看板.xlsx`。

## 13. A/B 测试 SOP

1. 写清假设、唯一变量、主指标和停止条件。
2. 选择同主题、相近发布时间和相似制作质量的样本。
3. 每组至少 3—5 条，优先累计 6—10 个可比样本。
4. 24 小时只看异常，72 小时做第一判断，7 天看搜索长尾。
5. 小样本阶段记录方向，不写“显著提升”。
6. 胜出项进入下一周 70% 主产能；失败项归档原因，不重复测试同一错误。
7. 不用虚假互动、刷量或删除低表现内容来污染结果。

测试台账见数据看板的 `A_B测试` 工作表。

## 14. 种子用户与 UGC SOP

### 14.1 招募

招募文案写清：内测性质、适用人群、支持格式、需要投入的时间、可能的 AI/OCR 错误、隐私说明、奖励、是否会邀请案例授权。体验与案例授权分开同意。

### 14.2 访谈

核心问题：

- 你同时准备多少类岗位？
- 之前如何针对 JD 改简历？
- 哪一步最费时间/最不确定？
- Reffo 哪个结果可信，哪个需要大量修改？
- 是否发现编造、遗漏或 OCR 错误？
- 完成后是否愿意为第二个岗位复用？
- 你愿意为什么付费，不能接受什么？

不引导用户说好评；保留负面反馈。

### 14.3 UGC 发布

1. 用户主动提交或接受邀请。
2. 完成独立授权和脱敏。
3. 运营只做事实、结构和隐私编辑，不改变用户真实观点。
4. 商业合作或奖励关系按要求披露。
5. 用户终审最终版本。
6. 发布后记录链接、授权期限和撤回状态。

## 15. 投放与达人合作 SOP

### 15.1 启动条件

必须同时满足：

- 自然内容有至少 2 个稳定胜出主题；
- 合规落地页、来源参数和产品激活埋点可用；
- 隐私、价格、退款和客服信息完整；
- 以激活/第二岗位/付费衡量，不只看曝光；
- 素材通过平台和内部 L3 审核。

### 15.2 达人筛选

优先真实求职经历、简历/职场/校招内容占比高、评论问题具体、粉丝与互动结构自然的小体量创作者。检查近 90 天商业内容比例、历史违规、虚假承诺、导流方式、受众岗位和内容质量。

合作 Brief 必须允许创作者表达真实限制和负面体验；不得要求“必须说拿到面试/Offer”。

### 15.3 投放复盘

按内容、达人、关键词和落地页分别记录：花费、曝光、主页/落地页访问、有效线索、获客、激活、第二岗位、付费、退款。没有来源追踪的数据不作为规模扩量依据。

## 16. 危机与异常处理

### 16.1 分级

| 级别 | 场景 | 动作 |
|---|---|---|
| C1 | 错别字、普通功能咨询、单个低风险误解 | 运营当天更正/回复并记录 |
| C2 | 大量用户误解能力、链接失效、生成质量异常、轻度投诉 | 暂停相关内容和投放；4 小时内产品/运营会商 |
| C3 | 未授权案例、隐私泄露、错误效果数据、平台重大违规、集中退款 | 立即下线相关素材和投放；通知负责人、法务、技术；保全记录 |
| C4 | 大规模数据泄露、监管/媒体问询、人身或求职结果严重争议 | 启动公司级事件响应；只有指定发言人对外 |

### 16.2 隐私事件最小动作

1. 停止传播、投放和继续处理相关素材；
2. 限制访问并保全必要证据，不扩大复制；
3. 确认数据类别、人数、平台、第三方和时间范围；
4. 通知技术、负责人和法务，按政策评估用户/监管通知；
5. 删除不必要副本并记录恢复、整改和复盘；
6. 不在公开评论区重复泄露内容。

### 16.3 公开回应原则

快确认、慢结论；只说已核实事实、正在采取的动作和下一次更新时间。不甩锅用户、模型、平台或外包；不承诺尚未验证的修复结果。

## 17. 归档与版本管理

每条内容归档：Brief、文案、源文件、成品、真实素材来源、产品证据、外部来源、授权、审批、发布链接、数据、评论问题和复盘结论。

平台规则每月至少检查一次；小红书专业号、投放、AI 标识、导流或活动规则发生变化时，当天更新本 SOP 的版本号和来源日期。
