## 引言和特别提示

欢迎使用 Reffo。Reffo 是面向中国大陆用户的浏览器 H5 AI 简历优化服务，可提供简历录入或上传、岗位描述（JD）录入或上传、文件文字识别、简历分析、岗位匹配、简历改写、面试建议、结果保存和下载等功能。

本政策说明运营者（以下称“我们”）如何处理您的个人信息，以及您如何行使个人信息权利。请您在使用前完整阅读，尤其关注以粗体标出的简历信息、第三方 OCR 和大模型处理、保存期限、删除、敏感个人信息与个人信息出境等内容。

**Reffo 不是仅在浏览器本地处理简历的工具。您保存源简历、上传文件或点击开始 AI 优化后，相关简历、JD、文件或中间处理结果会发送至 Reffo 后端，并可能根据您选择的功能发送给对象存储、OCR 或大模型服务商。**一般协议确认不能替代依法需要的单独同意；处理可能的敏感个人信息、向第三方 OCR 或 AI 服务发送信息前，应分别提示并取得您的主动确认。**当前代码尚未实现首次协议确认、上述单独同意和统一撤回入口；在这些能力完成前，不应面向真实用户处理简历。**

本政策根据截至更新日期的项目源代码、配置项和第三方公开规则编写。运营主体、生产环境托管商、Supabase 项目区域、实际大模型配置及适用的 API 合同尚未由代码完整证明，已按统一格式标为待补充或待确认。正式上线前必须完成这些确认并据实更新本政策。

## 一、适用范围

1. 本政策适用于 Reffo 浏览器 H5 页面、由页面调用的 Reffo 后端 API，以及为实现登录、同步、文件解析和 AI 生成而接入的第三方服务。
2. 本政策不适用于第三方独立提供、且不由我们控制的网站、产品或服务。您从 Reffo 跳转至第三方页面后，应阅读第三方规则。
3. 当前 H5 代码不申请相机、麦克风、精确位置、通讯录、相册等原生权限。仓库中的 iOS、Android 工程包含为历史或未来原生开发预留但当前业务代码未使用的权限声明；如未来发布原生应用，我们会先按实际功能精简权限、更新隐私告知，并依法重新取得授权。
4. 如未来新增账号注册、付费订阅、广告、营销、统计、公开用户案例、社交分享、原生权限或新的 AI 服务，本政策不会自动覆盖新增处理活动；我们会在启用前另行告知并依法取得同意。

## 二、我们处理个人信息的原则和法律基础

我们遵循合法、正当、必要、诚信、目的明确、公开透明、最小范围和最短期限原则。我们主要在以下基础上处理个人信息：

1. 为订立、履行您作为一方当事人的合同所必需，例如按您的请求生成简历分析或保存结果；
2. 取得您的同意或单独同意，例如处理可能的敏感个人信息、使用第三方 OCR、向第三方大模型发送简历，或发生个人信息出境；
3. 履行法定义务或法定职责所必需，例如网络安全、个人信息安全事件处置、依法配合监管；
4. 法律、行政法规规定的其他情形。

当具体处理不再具有相应基础时，我们会停止该处理，但法律要求保存或为建立、行使、抗辩法律请求所必要的除外。

## 五、文件解析和 AI 处理过程

### 1. PDF 简历和 JD 图片解析

浏览器读取文件后存在两条实际路径：

1. 已登录且 Supabase 配置可用时，前端把文件上传至 Supabase 私有 Storage，路径包含用户标识、用途、时间戳和原文件名；Reffo 后端根据路径下载文件；
2. 未登录或对象存储不可用时，前端将文件编码为 Base64 并通过 Reffo API 提交后端。

后端随后把完整文件的 Base64 数据、文件类型和用途发送给智谱 GLM OCR 接口，取得原始文字和结构化字段。前端允许您编辑解析结果。

**当前代码未实现用户通过页面删除 Supabase Storage 中 OCR 原始对象，也没有对象自动到期配置证据。数据库中的 `user_files` 只保存文件元数据，删除源简历或历史不会连带删除对象。正式上线前必须补齐对象删除/到期和删除结果校验。**

### 2. AI 分析、匹配和生成

点击开始 AI 优化后，Reffo 后端依次或按流程把以下信息组成提示词并调用大模型：完整简历、结构化简历分析、完整 JD、岗位结构、匹配结果、优化要求、生成的优化简历，以及生成面试建议所需的前序结果。

代码默认使用 `https://api.deepseek.com` 和 `deepseek-chat`，但 `OPENAI_BASE_URL`、`AI_MODEL`、`AI_FALLBACK_MODELS` 可在不同环境中覆盖。因此，“DeepSeek”为代码默认而不是对生产环境的绝对断言。运营者应以生产变量、账单和 API 合同确认实际服务商，并在变化前更新清单和单独告知。

### 3. 是否用于模型训练或产品改进

Reffo 代码中未发现将简历加入自有训练集、微调数据集、公开案例或营销素材的路径。**我们不会把您的简历用于训练 Reffo 自有模型，也不会在没有另行明确告知和取得相应同意的情况下用于产品改进、公开案例或营销。**

第三方是否使用 API 输入进行训练必须按适用于本项目的 API 合同、账号设置或书面承诺确认：

- DeepSeek 面向其直接服务用户的公开隐私政策载有改进和训练目的，但同时说明下游应用开发者处理终端用户个人信息不受该政策覆盖；公开开放平台条款要求开发者承担下游告知和授权义务。其 API 是否默认保存或训练本项目输入，尚不能由这些公开页面得出确定结论。
- 智谱开放平台公开隐私政策提及可能使用匿名化信息进行研究、产品改进或模型训练；本项目 OCR API 文件是否被保存、匿名化或训练，仍需适用合同确认。

**在取得“仅按指令处理、不得用于训练、保存期限明确、支持删除”的合同或书面确认前，不应将真实简历投入生产环境。**

### 4. 是否存在人工查看或审核

当前产品没有人工简历审核、人工润色或人工查看的常态功能。后端仅设置自动质量校验和诊断记录。为处理安全事件、故障排查、权利请求、投诉或依法配合监管，经过授权的技术或合规人员可能在最小必要范围接触数据。运营者的内部权限、审批、审计和保密制度尚需人工确认，未经授权的人员不得查看简历。

## 七、个人信息保存地点、期限和删除

### 1. 保存地点

1. 浏览器本地数据保存在您的当前设备和浏览器站点存储中。
2. Reffo 后端在本地开发环境可使用 SQLite；生产环境配置要求使用 Supabase。Supabase 项目区域由项目创建时选择，当前代码和脱敏配置名称无法证明实际区域。
3. Supabase 官方区域文档显示其项目可部署在新加坡、东京、首尔、美国、欧洲等 AWS 区域，未列出中国大陆区域。因此如生产环境使用托管 Supabase，存在个人信息存储在境外的高度可能，必须以项目控制台和合同核实。
4. 智谱公开政策称其在中国境内运营中收集产生的个人信息存储在中国境内。DeepSeek 面向直接服务的公开政策称在中国境内存储和处理，但是否覆盖 Reffo API 下游终端用户数据仍需确认。
5. Reffo H5、API、CDN 和域名的实际托管商与节点地区尚未由仓库部署配置证明。

### 2. 保存期限

| 位置/数据 | 当前技术实现 | 删除或到期 |
|---|---|---|
| 浏览器源简历、历史、最近结果 | 无自动到期 | 业务页面删除相应源简历/历史、浏览器清站点数据或浏览器回收；最近结果无独立清除入口 |
| Reffo 数据库源简历、历史 | 无自动到期字段或定时清理 | 用户删除、服务终止后按政策处理；正式上线前须制定明确最短期限 |
| Supabase Storage OCR 原始文件 | 未发现自动到期或自助删除 | **当前页面无法删除；正式上线前必须实现** |
| `user_files` 文件元数据 | 无自动到期 | 当前无前端删除入口；须随对象删除或权利请求删除 |
| Harness 调用诊断 | 默认 7 日，最多 1,000 次运行 | 初始化和定期维护时按限制清理 |
| 浏览器登录令牌 | 至退出登录、清站点数据或令牌到期 | 当前退出登录只清本地；服务端撤销待确认 |
| Supabase/智谱/DeepSeek/托管方日志和备份 | 取决于适用合同和配置 | **待第三方或运营者确认** |

如法律法规要求更长保存，我们仅在法定目的和期限内保存，并限制其他处理；期限届满后删除或匿名化。删除是指使信息在日常业务系统中不可被检索和访问。因备份技术限制不能立即删除时，我们会隔离并停止除存储和必要安全保护外的处理，直至备份轮换清除。

### 3. 用户主动删除后的处理

1. 业务页面可以删除当前源简历或单条/全部生成历史。源简历删除请求失败时会提示失败；生成历史 store 当前会捕获服务端删除错误后仍清除本地记录，因而本地消失不必然代表服务端已经删除。
2. 直接使用浏览器“清除站点数据”只删除当前浏览器副本，不删除服务端、对象存储、第三方副本或账号。
3. 当前删除服务端源简历和历史**不会**连带删除 Supabase Storage 中 OCR 原始文件、`user_files` 元数据、Supabase Auth 账号、第三方 API 副本或备份。
4. 当前没有统一的数据清除、撤回同意或账号注销入口。要求进一步删除、限制处理或注销账号，请通过本政策联系人提出。运营者应在正式上线前为对象文件、同意撤回和账号提供实际可执行的能力，并修复生成历史删除失败仍显示本地删除的语义。

## 八、个人信息出境

**当前无法确认不存在个人信息出境。**Supabase 项目区域、H5/API 托管位置和生产大模型服务地址均可能影响结论。即使第三方主体为境内公司，其子处理者或灾备也需合同核实。

如确认将个人信息提供给境外接收方，我们会在传输前：

1. 专门告知境外接收方名称、联系方式、处理目的、方式、信息种类、保存期限和您行使权利的方式；
2. 对敏感个人信息和出境分别取得单独同意，不用一次概括勾选替代；
3. 开展并留存个人信息保护影响评估；
4. 根据适用条件通过安全评估、个人信息出境标准合同、认证或法律规定的其他机制；
5. 采取加密、访问控制、最小化、合同监督和删除协助等措施。

在完成上述核验和机制前，生产环境不得处理真实简历。

## 九、敏感个人信息

敏感个人信息是一旦泄露或非法使用容易导致人格尊严受侵害或人身、财产安全受危害的信息。不满十四周岁未成年人的个人信息属于敏感个人信息。简历中的普通联系方式和履历不当然全部属于法定敏感个人信息，但组合后具有较高泄露和求职歧视风险；简历还可能包含身份证件、特定身份、政治面貌、宗教信仰、医疗健康、金融账户、精确位置等法定敏感信息。

Reffo 的基本功能不要求上述非必要敏感字段。请先删除。确需处理时，我们会在处理前说明具体信息、必要性、对权益的影响、保护措施并取得单独同意。您拒绝后可继续阅读协议或手动处理不含该信息的内容，但不能使用依赖该信息的功能。

## 十、未成年人个人信息

本服务主要面向成年求职者，不面向不满十四周岁的未成年人。我们不会主动要求儿童提交简历或使用 AI 优化。若我们发现未经监护人同意处理了儿童个人信息，会停止相关服务并及时删除或匿名化；法律另有保存要求的除外。监护人可以通过本政策联系方式申请查阅、更正、删除或撤回同意。十四周岁以上未成年人应在监护人指导下使用，并避免提交不必要信息。

## 十一、您的个人信息权利

在法律规定范围内，您有权：

1. **查阅和复制**：通过页面查看本地和同步的源简历、历史、最近结果；对页面无法提供的副本可联系请求。
2. **更正和补充**：在简历编辑、JD 编辑和结果编辑中修改内容，或联系我们更正账号和元数据。
3. **删除**：使用现有源简历/历史删除操作或浏览器站点数据设置处理相应本地记录；对服务端、对象存储、账号、第三方和备份提出补充请求。现有生成历史删除存在服务端失败后仍清本地的缺陷，请以服务端确认或联系人答复为准。
4. **撤回同意**：当前没有产品内统一入口；可通过本政策联系人撤回相应同意。撤回不影响撤回前处理的合法性。正式上线前应增加可分项撤回入口。
5. **限制或拒绝处理**：在对准确性、合法性有争议时，可要求限制处理；法律赋予拒绝权时可提出拒绝。
6. **解释处理规则**：要求我们说明自动化处理、第三方、保存和权利响应方式。
7. **转移**：符合法定条件并且技术可行时，请求将信息转移至您指定的个人信息处理者。
8. **注销账号**：当前没有产品内入口；可通过联系人提出。退出登录不等于注销。
9. **为逝者行使权利**：近亲属可为合法、正当利益依法对逝者相关个人信息行使查阅、复制、更正、删除等权利，逝者另有安排的除外。

为保护信息安全，我们可能核验身份、请求范围和授权。我们原则上在十五个工作日内答复；法律另有规定或情况复杂需延长时会说明。拒绝请求时会告知理由和投诉途径。合理请求原则上不收费；对明显重复、超出合理限度的请求，可依法收取必要成本或拒绝并说明理由。

## 十二、个人信息安全保护

当前代码已采用或设计采用以下措施：

1. HTTPS 传输和 Bearer 令牌认证；
2. Supabase 私有对象存储、数据库行级安全策略和按用户路径隔离；
3. 生产环境强制身份认证和数据库配置校验；
4. 诊断记录优先保存哈希摘要和元数据，不设计为持久化完整提示词及输出；
5. 用户可通过现有业务控件删除源简历或历史，也可通过浏览器清除本地数据；撤回同意和统一清除入口尚待实现；
6. 以最小必要权限、内部访问控制、人员保密、安全审计、漏洞处置和备份保护等管理措施保护信息。

第 6 项内部制度、生产密钥轮换、备份、访问审计、渗透测试、应急演练和供应商管理情况仍需运营者落实并留证。**当前前端两层请求调试日志仍会输出完整请求正文，可能包含简历、JD 或文件 Base64，这是上线前必须整改的安全缺陷。**浏览器 localStorage 令牌和简历还可能受到共用设备、恶意扩展、XSS 或设备失窃影响；请妥善管理设备并及时清除。任何网络系统都存在风险，我们不承诺“绝对安全”或“永不泄露”。

## 十三、个人信息安全事件

发生或可能发生个人信息泄露、篡改、丢失时，我们将立即启动应急处置，采取隔离、停止接口、修复漏洞、重置凭证、追踪影响、删除或限制异常数据等补救措施，并按法律要求向履行个人信息保护职责的部门报告。

需要向个人告知时，我们会以弹窗、站内通知、邮件、电话或公告等合理方式告知涉及的信息种类、原因、可能危害、已采取和可自行采取的措施及联系人；能够采取措施有效避免危害且法律允许不逐一通知的，依法处理，但监管部门要求通知时仍会通知。

## 十四、第三方链接和责任边界

第三方独立页面由其自行运营，其直接收集的信息受其规则约束。对于我们委托第三方处理的信息，我们依法对受托方进行尽职调查、签订数据处理条款并监督；不能以第三方故障或条款为由免除我们依法承担的选择、告知、安全和权利保障责任。若第三方超出委托独立处理，其应依法承担相应责任，我们也会协助您行使权利。

## 十五、政策更新和重新取得同意

我们可能因法律、功能、第三方或安全措施变化更新本政策。出现处理目的、信息种类、第三方名称或关系、保存地点和期限、出境、敏感信息、自动化决策或权利方式等重大变化时，我们会在服务内显著提示，更新版本号，并要求您重新主动确认。依法需要单独同意的事项会再次分别取得，不以“继续使用即视为同意”替代。
