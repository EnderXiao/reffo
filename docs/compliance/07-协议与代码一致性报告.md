# Reffo 协议—代码一致性检查报告

**检查日期：2026 年 8 月 22 日**  
**协议版本：1.0.0**  
**检查范围：`frontend/Taro/reffo-taro`、`frontend/Web`、`backend`、Supabase migrations、环境变量名称、原生清单和第三方公开规则**  
**说明：本次按用户调整后的范围仅生成文档，未修改 H5 页面和交互。**

## 一、总体结论

协议正文已按真实数据流撰写：Reffo 不是纯本地工具，会把简历/JD/文件发往自建后端、Supabase、智谱 OCR 和当前大模型；没有虚构收费、退款、产品内账号注销、广告、统计或 H5 原生权限。

协议还如实披露无法确认的生产主体、托管地区、第三方 API 保存/训练和出境情况，并未把推断写成结论。

但是，当前代码不具备让两份协议合法、有效落地所需的展示与同意能力，也存在删除、日志、AI 标识和第三方合同方面的重大缺口。协议文本准确披露这些缺口，不代表缺口已被修复。

## 二、逐项一致性检查

| 检查项 | 当前代码事实 | 协议/清单表述 | 一致性结论 | 上线前动作 |
|---|---|---|---|---|
| 是否纯本地处理 | 保存/生成会向 Reffo API发送；文件和文本进一步到第三方 | 明确“不是仅在浏览器本地处理”并列出路径 | **一致** | 所有宣传不得写“纯本地”“简历不离开设备” |
| 是否发送第三方 AI | 默认 DeepSeek 兼容 API；环境变量可换地址和模型 | 写“代码默认 DeepSeek，生产可替换，实际主体待确认” | **一致** | 核对生产变量、账单和合同后更新名称 |
| 是否发送第三方 OCR | GLM OCR 收到完整文件 Base64 | 写智谱 GLM OCR 接收完整 PDF/图片 | **一致** | 确认文件留存、训练、地区和删除 |
| 是否使用 Supabase | Auth、PostgREST、Storage 均有路径，生产强制 Supabase | 列为认证、数据库、对象存储，地区未知 | **一致** | 补项目区域、DPA、日志和备份规则 |
| 协议声称不使用 Cookie | 应用未设置 Cookie；托管/第三方未知 | 仅写“应用代码当前不设置”，保留生产验证 | **一致且审慎** | 生产做 Cookie/响应头扫描 |
| localStorage | 完整源简历、历史、最近结果、令牌、引导和偏好 | 隐私政策逐键披露，含旧版键 | **一致** | 增加期限、统一清除和安全提示 |
| sessionStorage | 页面过渡、卡片位置等 | 已披露 UI 会话状态 | **一致** | 无主要风险 |
| IndexedDB/Service Worker/CacheStorage | 未发现 | 明确不存在 | **一致** | 新增 PWA 时更新 |
| 自动收集 IP/设备 | 业务代码不落库；网络/托管可能记录 | 区分应用代码和托管/第三方未知日志 | **一致** | 补生产访问日志清单 |
| 保存期限 | 源简历、历史、Storage 对象无自动到期；Harness 7 日/1,000 | 如实写当前期限和缺口 | **一致，但实现不合规风险高** | 制定并实现最短期限和到期任务 |
| 本地清除 | 业务页可删除源简历/历史；最近结果无统一入口；浏览器可清站点数据 | 政策按位置说明，没有虚构“隐私与数据”页 | **一致** | 增加统一清除并说明范围 |
| 服务端源简历删除 | store 调服务端成功后清本地，失败通常提示 | 政策按实际说明 | **一致** | 验证鉴权、删除日志和备份 |
| 服务端历史删除 | history store 捕获远端失败后仍清本地 | 政策和 AI 说明明确“本地消失不代表服务端成功” | **一致披露，但产品有高风险缺陷** | 失败不得清本地或显示成功；增加测试 |
| OCR Storage 删除 | 无对象删除 API/自动过期；`user_files` 不级联 | 明确无法自助删除、属上线阻断 | **一致披露，功能未完成** | 实现对象+元数据删除、重试和结果校验 |
| 同意/协议版本记录 | 当前不存在 | 协议注明尚未实现；矩阵列为建议 | **一致披露，无法形成有效线上同意** | 实现非预勾选确认、版本和审计记录 |
| 敏感信息单独同意 | 没有拦截或记录 | 政策注明尚未实现，矩阵列最高优先级 | **一致披露，发布阻断** | 处理前提供必要性/影响和单独同意 |
| OCR/第三方 AI 单独同意 | 点击上传/生成直接发请求 | 协议/矩阵明确现状及应当触发点 | **一致披露，发布阻断** | 在网络请求前分项拦截；拒绝不发请求 |
| 出境告知和单独同意 | 地区未知，无出境确认 | 协议不承诺无出境并列为阻断 | **一致披露，发布阻断** | 确认地区、PIPIA、法定机制、专门告知和单独同意 |
| 撤回同意 | 没有同意记录或统一撤回入口 | 政策明确只能联系，矩阵列未实现 | **一致披露** | 增加分项撤回，不与删除混同 |
| 账号体系 | 有邮箱密码登录和 Supabase Auth，无公开注册和注销；退出只清本地 | 没有虚构注销，明确当前限制 | **一致** | 补服务端撤销/注销或移除账号功能 |
| Reffo 是否训练 | 未发现训练/微调/案例路径 | 承诺 Reffo 不用于自有训练或产品改进 | **一致（仓库范围）** | 组织制度禁止仓库外导出训练 |
| 第三方是否训练 | 代码不能证明；公开规则存在不确定 | 明确待 API 合同和控制台确认 | **一致且审慎** | 获取无训练、短留存和删除承诺 |
| 人工查看 | 无常态人工审核；运维可理论访问 | 写无常态流程、必要排障最小访问、内部制度待确认 | **一致** | 建权限、审批和访问审计 |
| 前端请求日志 | `api.ts` 和 `request.ts` 均输出完整 `data`，可能含简历/JD/Base64 | 隐私政策和清单明确披露为安全缺陷 | **一致披露，严重风险** | 只记方法/URL/状态/请求ID；生产关闭正文日志 |
| 后端日志 | 多为文件名、类型、大小、耗时和错误，无统一请求正文 logger | 政策披露元数据和错误风险 | **基本一致** | 脱敏文件名和错误；禁 Base64/令牌/正文 |
| Harness | 主要存哈希、摘要、模型、质量问题和错误，默认 7 日/1,000 | 写“设计上不存完整原文”，保留错误片段风险 | **一致** | 做 PII 自动扫描和期限测试 |
| 收费/支付/退款 | 未发现 | 用户协议明确当前无付费/订阅/退款 | **一致** | 收费前另行展示和确认 |
| 广告/营销/统计 | 未发现 | 明确不存在 | **一致** | 新增时默认关闭并更新政策 |
| 公开用户案例 | 未发现 | 明确不存在，未来逐案授权 | **一致** | 不得用一般许可替代案例授权 |
| 正式/娱乐模式 | 当前只有正式求职流程；Landing 有虚构预设 | 协议明确无娱乐模式、预设仅演示、虚构不得求职 | **一致** | Landing 增加显著“演示/虚构”标识 |
| AI 输出风险 | 首页底部有一般免责声明；模型可能补全/改写 | 用户协议加粗说明错误、无录用保证和核验义务 | **基本一致** | 在生成前和结果/导出时持续提示 |
| AI 显式标识 | 首页只有一般提示；结果的每项内容无专门标识 | 用户协议准确说明现状和必须整改 | **一致披露，当前实现不足** | 结果、下载、复制、API 全链路标识 |
| AI 隐式标识/导出日志 | Markdown 下载是原始优化正文，无元数据和日志 | 用户协议、矩阵、风险报告均列未实现 | **一致披露，发布阻断** | 按标识办法和配套标准实现/验证 |
| 用户内容真实性 | 代码无法完全验证生成事实 | 协议要求逐项核验、禁止虚构 | **一致** | 增加来源追踪、改写 diff 和事实约束 |
| 用户内容许可 | 技术上仅为解析/存储/生成复制传输 | 协议许可限定目的、期限、地域和受托方，排除训练/营销 | **一致** | 确保第三方合同不要求更宽许可 |
| 服务终止/停止运营 | 无公告和导出 SOP | 用户协议规定提前告知和导出/删除 | **制度与代码未落地** | 建立停止运营流程和公告能力 |
| 联系/投诉/权利请求 | 无有效主体和联系方式 | 统一待人工补充，没有虚构 | **文本诚实但无法实际行权** | 上线前补全并实测渠道 |
| 原生权限 | Android/iOS 清单含未使用的相机、麦克风、位置、通讯录、相册等 | H5 政策只声明 H5 不使用，并提示原生另审 | **H5 一致；原生不可直接上线** | 删除超配权限、更新原生隐私清单和弹窗 |

## 三、隐私政策、用户协议与清单交叉核验

| 主题 | 隐私政策 | 用户协议 | AI说明/清单 | 结果 |
|---|---|---|---|---|
| 运营者 | 统一待补充 | 统一待补充 | 不虚构主体 | 一致；上线阻断 |
| 实际模型 | 默认 DeepSeek、可覆盖 | 同口径 | 第三方清单同口径 | 一致 |
| OCR | 智谱 GLM OCR、完整文件 | 第三方条款说明 | 数据流/清单一致 | 一致 |
| Supabase | Auth/DB/Storage、区域未知 | 引用隐私规则 | 清单列可能出境 | 一致 |
| 保存期限 | 当前实现和待确认期限分开 | 不作相反保证 | 各位置一致 | 一致 |
| 删除 | 本地、数据库、Storage、账号、第三方分开 | 不把退出写成注销 | AI说明列实际失败语义 | 一致 |
| 训练 | Reffo 不训练，第三方待确认 | 有限许可排除训练 | 第三方报告待合同 | 一致 |
| AI 标识 | 不是隐私核心，但风险交叉提示 | 如实写首页提示和下载无标识 | 矩阵/风险列未实现 | 一致 |
| 收费 | 不涉及支付收集 | 当前无收费/退款 | 第三方清单无支付 | 一致 |
| 同意实现 | 明确当前缺失 | 规定应主动接受的生效方式 | 矩阵标未实现 | 一致披露，但产品尚不具备上线条件 |

## 四、旧版 `frontend/Web` 的额外风险

旧版 React/Vite MVP 仍保留在仓库：

- 使用 `reffo_resume_markdown`、`reffo_jd_text`、`reffo_last_result` 保存完整内容；
- 向 `/api/v1/mvp/process` 发送完整简历和 JD；
- 可以复制 AI 结果；
- 同样没有协议页、首次确认、单独同意、长期入口、撤回、可靠服务端删除或 AI 结果标识。

如果旧版仍部署，必须与 Taro H5 一并纳入整改；否则应停止部署并说明旧数据清除。不能只给新 H5 增加协议而让旧入口继续无告知处理。

## 五、协议提供了权利但代码没有入口的项目

这些权利来自法律或完整协议的必要条款，不能因为代码暂未实现就从协议删除；但上线前必须提供可操作方式：

1. 首次协议阅读和非预勾选接受；
2. 敏感信息、OCR、第三方 AI 和出境的单独同意；
3. 分项撤回和限制处理；
4. 统一本地数据清除和可靠服务端删除；
5. OCR 对象、元数据、账号和第三方副本删除申请；
6. 查阅、复制、更正、转移和账号注销；
7. 协议历史版本与重大更新重新确认；
8. 投诉、举报、侵权和个人信息联系人；
9. 生成内容显式/隐式标识与导出记录；
10. 停止运营时的数据导出和删除。

在产品入口完成前，至少要有真实可用并能按时响应的联系渠道；但联系渠道不能长期替代可以合理自动化的删除、撤回和注销功能。

## 六、上线前回归检查

1. 全仓搜索新网络请求、域名、SDK、存储键、Cookie、IndexedDB 和 Service Worker；
2. 无本地存储状态首次打开：协议可读、checkbox 不预勾选、拒绝不发业务请求；
3. 分别拒绝 OCR、敏感信息、第三方 AI 和出境，确认网络请求没有发生；
4. 删除成功/失败路径逐一核验浏览器、数据库、Storage、Auth、Harness、第三方和备份；
5. 浏览器控制台、后端、托管日志不得出现简历正文、JD、Base64、令牌或密码；
6. 下载、复制、API、截图/分享提示中验证显式和隐式 AI 标识；
7. 对照生产供应商、项目区域、合同、子处理者和保留期限更新清单；
8. 验证协议版本变化会重新提示并保留历史记录；
9. 验证联系、投诉、查阅、删除、撤回和注销流程能实际完成；
10. 原生发布前重新检查 Manifest、Info.plist、PrivacyInfo、SDK 和运行时权限。
