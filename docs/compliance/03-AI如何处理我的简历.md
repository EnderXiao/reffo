# AI 如何处理我的简历

**版本：1.0.0**  
**更新日期：2026 年 8 月 22 日**  
**生效日期：2026 年 8 月 22 日**

这是一份面向用户的分层告知，说明 Reffo 当前代码中简历和目标岗位 JD 的实际流向、保存位置、第三方和删除效果。完整规则请阅读 [《Reffo 隐私政策》](./01-隐私政策.md)。

## 一、先说结论

**Reffo 不是“所有内容只在浏览器本机处理”的应用。**

- 您输入或上传的内容会先被浏览器读取和显示；
- 保存源简历时，完整简历会写入浏览器本地，并发送至 Reffo 后端数据库；
- 上传 PDF 简历或 JD 图片时，完整文件会进入 Reffo 后端或 Supabase 私有对象存储，再发送给智谱 GLM OCR；
- 点击 AI 优化时，完整简历、JD 和处理中的结构化内容会由 Reffo 后端发送给当前配置的第三方大模型；代码默认使用 DeepSeek，但生产环境可通过环境变量更换；
- 生成历史会同时保存在当前浏览器和 Reffo 数据库；
- 当前代码尚不能从产品页面删除 OCR 原始对象存储文件，也不能直接证明第三方 API 已删除副本。

仅阅读页面不会主动把新的简历文件发送给 OCR 或大模型；但当前代码在您选择文件或点击保存、AI 优化后会直接开始相应处理，尚无单独同意拦截。

## 二、从选择文件到生成结果的数据流

```text
您输入/选择文件
  ├─ 浏览器内存：读取、预览、Base64 编码（临时）
  ├─ 浏览器 localStorage：源简历、历史、最近结果（持久）
  └─ Reffo API
       ├─ Reffo 数据库：源简历、JD、生成历史
       ├─ Supabase Storage：PDF/图片原始文件（登录且配置可用时）
       ├─ 智谱 GLM OCR：完整 PDF/图片 → 识别文字
       └─ 当前大模型（代码默认 DeepSeek）：简历/JD/中间结果 → 分析与生成
```

### 1. 手动输入或粘贴

输入框内容先存在页面内存。保存源简历后，完整 Markdown 简历会写入本地 `latest_source_resume`，同时经 `/api/v1/source-resume` 写入服务端。输入 JD 并点击开始生成后，JD 会进入最近结果和历史，并发送给大模型。

手动输入可以避免把原始 PDF 或图片发送给 OCR，但**不能**避免保存和 AI 优化所需的服务端与大模型传输。

### 2. 上传 PDF 简历

浏览器读取完整文件。当前有两种技术路径：

1. 已登录且 Supabase 配置可用：文件直传 Supabase 私有 Storage，路径格式包含用户标识、`resume` 用途、时间戳和文件名；Reffo 后端再下载该对象；
2. 未登录或对象存储不可用：文件编码为 Base64，通过 Reffo API 直接提交。

Reffo 后端把完整文件发送给智谱 GLM OCR，取得原始文字和结构化简历。文件名、类型、大小、用途、存储桶和路径还会写入 `user_files` 元数据表。

### 3. 上传 JD 图片

流程与 PDF 类似，用途标记为 `jobDescription`。识别出的 JD 会回填到输入框供您编辑，然后作为岗位匹配和生成输入。

### 4. AI 分析和生成

点击开始 AI 优化后，Reffo 后端先分析简历，再结合完整 JD 进行匹配，之后生成优化简历和面试建议。不同步骤可能向模型发送：

- 完整简历 Markdown；
- 姓名、联系方式、教育、任职、项目、技能和证书等简历字段；
- 完整 JD、公司、岗位、地点；
- 结构化分析、硬性要求、匹配差距、优化建议；
- 前一步已经生成的简历或分析结果；
- 为质量校验而重新提交的待检查内容。

这些内容不是匿名统计数据，模型服务商有可能据此识别您或关联您的履历。

## 三、哪些内容保存在本机

| 本地位置 | 内容 | 当前期限 | 用户如何删除 |
|---|---|---|---|
| `localStorage.latest_source_resume` | 完整源简历、标题、原文件名、来源和时间 | 无自动到期 | 现有源简历删除操作，或浏览器清站点数据 |
| `localStorage.resume_histories` | 原简历、JD、优化简历、分析、建议、面试内容、评分和上下文 | 无自动到期 | 业务页逐条/全部删除，或浏览器清站点数据；应注意服务端删除结果可能失败 |
| `localStorage.latest_result_session` | 最近生成结果、完整源简历和 JD、进度 | 无自动到期 | 当前无独立按钮；浏览器清站点数据 |
| 旧版 MVP 三个 `reffo_*` 键 | 旧版简历、JD 和结果 | 无自动到期 | 旧版重置或浏览器清站点数据 |
| `localStorage.reffo.auth.session.<env>` | Supabase 访问令牌、刷新令牌、到期时间、用户标识、邮箱 | 至退出、到期或清除 | 退出登录或浏览器清站点数据；不等于服务端账号注销 |
| `sessionStorage` 页面键 | 返回状态、卡片位置、动画快照 | 当前标签页会话 | 关闭标签页、页面流程清理或浏览器清除 |

Reffo 当前没有 IndexedDB、Service Worker 或 CacheStorage 业务数据。应用代码当前不设置 Cookie。

## 四、哪些内容同步到服务端

### 1. Reffo 业务数据库

- `source_resumes`：完整源简历、标题、来源、原文件名和时间；
- `resume_histories`：公司、岗位、完整原简历、完整 JD、优化内容、建议、评分、完整处理结果和页面上下文；
- `user_files`：文件名、类型、大小、用途、存储桶、对象路径和时间；
- `profiles`：Supabase 用户标识和时间信息。

生产环境配置要求使用 Supabase；本地开发也可使用 SQLite。本地 SQLite 模式以共享的开发用户标识运行，不应被当作多人生产隔离方案。

### 2. 对象存储

Supabase Storage 保存上传的 PDF 或图片原始对象。代码使用私有存储桶和用户路径隔离；但仓库没有文件自动过期配置，也没有从 UI 删除对象的实现。**删除源简历、删除历史或清除本机，不会删除这些原始对象。**

### 3. 调用诊断数据库

Harness SQLite 保存步骤、模型、请求标识、令牌数、耗时、请求/输出哈希摘要、质量评估和错误，默认保留 7 日且最多 1,000 次运行。代码目标是不保存完整提示词和完整输出；但错误消息、评估问题或模型摘要仍应持续做个人信息审计。

## 五、哪些第三方参与处理

| 第三方 | 收到什么 | 为什么 | 地区、保存和训练现状 |
|---|---|---|---|
| Supabase | 邮箱、用户标识、令牌、完整简历/JD/历史、原始文件、文件元数据、网络技术信息 | 登录、数据库、私有对象存储 | 项目区域决定数据所在地；实际区域未知，官方区域多为境外 AWS 节点，可能出境。DPA 和删除规则待运营者签署/确认 |
| 北京智谱华章科技股份有限公司（GLM OCR） | 完整 PDF/图片、类型、用途、识别文字、网络信息 | OCR 提取文字 | 公开政策称境内存储和最短必要期限，但本项目 API 具体留存、训练、备份和删除协助待合同确认 |
| DeepSeek API 实际签约主体或生产环境实际模型商 | 完整简历、JD、中间分析和生成内容、调用信息 | 简历分析、岗位匹配、改写、面试建议 | 代码默认 DeepSeek；生产配置可更换。下游 API 数据是否训练、保存多久及删除机制待适用合同/控制台确认 |
| H5/API 托管和 CDN | IP、请求时间、请求头；API 运行时处理的业务正文 | 页面分发、后端运行、安全 | 实际供应商、节点、日志字段和期限尚未由仓库证明 |

第三方公开政策并不当然等于与 Reffo 签订的 API 数据处理合同。正式上线前，运营者应取得并保存适用合同、DPA、项目区域截图、无训练设置、保留期限和删除协助承诺。

## 六、会不会用于训练或人工查看

### Reffo 自己

当前代码没有把简历写入训练集、微调集、公开用户案例或营销素材的路径。Reffo 不应把您的数据用于自有模型训练或产品改进，除非以后另行明确说明目的、范围、期限、退出方式并取得相应同意。

当前没有常态化人工简历审核或人工润色功能。安全排障、响应删除请求、投诉或依法配合时，受授权人员可能在最小范围查看。运营者仍需建立内部权限、审批和访问审计制度。

### 第三方

目前不能仅凭公开政策承诺 DeepSeek 和智谱 API “绝不保存、绝不训练”：

- DeepSeek 面向直接服务的公开隐私政策包含服务改进和模型训练描述，同时声明下游开发者处理终端用户信息不在其政策覆盖范围；
- 智谱公开政策包含匿名化信息用于研究、产品改进或训练的描述；
- Reffo 尚未在仓库保存与两家服务商适用的企业/API 数据条款。

因此，“禁止训练、限定保存、支持删除”是生产上线前的合同确认事项，而不是已经由代码证实的事实。

## 七、删除数据后，各位置会怎样处理

### 1. 使用现有源简历或历史删除操作

源简历删除会调用服务端接口，成功后清除本地源简历；失败时通常保留并提示。生成历史的逐条/全部删除也会请求服务端，但当前 history store 会捕获服务端错误后继续清除本地，因此本地记录消失不代表服务端一定删除成功。

这些操作不会删除：

- Supabase Storage 中的 OCR 原始对象；
- `user_files` 元数据；
- Supabase Auth 账号；
- Harness 中在 7 日/1,000 次限制内的调用诊断；
- 第三方 API 日志、备份或副本。

### 2. 使用浏览器“清除站点数据”

会删除当前浏览器中的源简历、历史、最近结果和本地登录令牌，但不会自动删除 Reffo 数据库、Supabase Storage、Supabase Auth 账号、第三方 OCR/模型副本或备份。

### 3. 撤回同意

当前代码没有首次协议确认、OCR/第三方 AI 单独同意记录或分项撤回入口。正式上线前必须补齐。在此之前，您只能通过个人信息保护联系人提出停止处理和删除请求；撤回不等于删除，也不影响撤回前处理的合法性。

### 4. 退出登录与账号注销

退出登录只清除本地 Supabase 会话，不注销账号、不删除数据库或对象。当前没有自助账号注销入口。如需注销、删除原始对象或要求第三方协助删除，请联系：**【待人工补充：个人信息保护联系人及可用邮箱、电话】**。

## 八、您如何降低风险

1. 上传前删除身份证件、住址、金融、健康、政治面貌、宗教信仰等非必要内容；
2. 不希望上传原始文件时，选择手动粘贴经过脱敏的文字；
3. 不要上传他人的简历、商业秘密或未经授权的客户/项目材料；
4. 当前产品缺少必要的单独同意交互；该缺陷修复前不要输入真实简历或启用生产处理；
5. 对 AI 输出逐项核验，删除编造、夸大或无法证明的内容；
6. 在共用设备完成使用后清除本机数据并退出登录；
7. 删除时分别处理本机、服务端、对象存储、账号和第三方，不要把一次清理理解为全部位置已删除。
