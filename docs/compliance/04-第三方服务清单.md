# Reffo 第三方服务清单

**审计基准日：2026 年 8 月 22 日**  
**对应协议版本：1.0.0**

## 一、结论

当前项目并非无第三方服务。代码明确接入 Supabase、智谱 GLM OCR 和兼容 OpenAI API 的大模型；大模型默认地址和模型指向 DeepSeek。H5/API 的实际云托管、CDN、域名和网络服务商没有可证明实际部署的仓库配置，不能根据调研文档中的候选方案认定为已经使用 Render 或 Cloudflare。

第三方是否属于受托处理者，不取决于协议中如何称呼，而取决于双方实际决定处理目的和方式的程度及合同约束。下表的“拟作为受托处理者”是合规目标，不代表适用合同已经签署。

## 三、第三方关系的合规判断

### 1. Supabase

Reffo 决定使用数据库、认证和存储的目的，Supabase 提供通用技术能力。对按 Reffo 指令存储和返回的数据，目标关系应为《个人信息保护法》第二十一条所称委托处理。运营者需：

- 与适用主体签署 DPA/委托处理条款；
- 约定目的、期限、方式、种类、保护措施和双方权利义务；
- 核验并监督子处理者；
- 确认项目区域、备份、日志和删除；
- 在委托终止时要求返还或删除；
- 如果位于境外，完成中国法下出境义务，而不能只依赖 Supabase 面向 GDPR 的标准合同条款。

Supabase 为自身防欺诈、计费、账号管理或安全独立决定目的的处理，可能不是受托处理，应在合同和隐私政策中分别识别。

### 2. DeepSeek/实际模型商

代码通过 OpenAI SDK 调用兼容端点；生产环境可以更换地址和模型。必须以生产环境变量名称对应的实际账单、合同和网络流量确认服务商，不能仅凭类名 `DeepSeekProvider` 断言。

公开 DeepSeek 隐私政策说明其面向直接服务收集输入并可能用于改进或训练，同时明确下游应用开发者对终端用户个人信息承担处理者责任；开放平台条款要求开发者履行告知、授权和权利响应。要将模型商认定为 Reffo 的受托处理者，还需取得适用于 API 的明确条款，包括：

- 不将输入、输出用于通用模型训练或其他独立目的；
- 明确保留期限，最好启用零/短期数据保留；
- 明确数据中心和子处理者；
- 支持删除、访问、事件通知和审计；
- 模型服务终止后删除；
- 不得从简历建立独立画像或联系用户。

未取得前，属于**上线阻断风险**。

### 3. 智谱 GLM OCR

智谱公开政策称境内存储、最短必要期限、提供删除渠道，并提醒开发者不要非必要输入个人信息及在提供他人信息前取得授权。但本项目发送的是完整 PDF/图片，需要比一般文本调用更高的合同保障。运营者应确认：OCR 请求内容是否落盘、日志是否含文件、是否进入训练、保留多久、备份轮换和删除 API/工单时限。

## 四、当前明确不存在或未启用的外部服务

代码审计未发现以下服务的实际调用，因此不列为正在共享个人信息的第三方：

- 广告和营销平台；
- 产品分析/埋点平台；
- 第三方错误监控；
- 支付、订阅和退款平台；
- 邮件营销、短信营销；
- 社交登录；
- 用户案例公开发布平台；
- Jina 网页研究服务（仅存在示例/预留变量，主流程未发现调用）。

React Native/Expo 依赖和原生清单中的相机、定位、麦克风、通讯录等权限，不等于当前 H5 已向相关服务提供数据。原生版本发布前必须独立审计、删去无用权限并更新清单。

## 五、上线前必须补证的第三方材料

1. Supabase 项目区域截图、适用 DPA、子处理者清单、备份/日志期限、Storage 删除方案；
2. DeepSeek 或实际模型商的法定签约主体、API 数据条款、无训练设置、保存期限、服务器地区和删除协助；
3. 智谱 GLM OCR 的 API 数据条款、文件留存、训练、日志、底层云和删除协助；
4. H5、API、CDN、DNS、TLS 和数据库实际托管商名称、法定主体、隐私政策、节点地区、日志字段和期限；
5. 个人信息出境影响评估和适用的法定机制；
6. 委托处理合同中的安全事件通知、权限控制、分包、审计、终止删除条款。
