# Reffo 待补充信息与合规风险报告

**审计基准日：2026 年 8 月 22 日**  
**审计对象：仓库代码、示例/分环境配置名称、数据库迁移、前后端依赖、原生清单和第三方公开规则**

> 本报告区分代码事实、配置推断和法律判断。它不是对运营者取得全部资质、合同或监管结论的替代。高风险/上线阻断项未关闭前，不应处理真实用户简历。

## 一、最高优先级结论

1. **服务不是纯本地处理。**完整简历、JD、PDF/图片和中间结果会到 Reffo 后端、Supabase、智谱 OCR 和当前大模型。
2. **很可能发生个人信息出境，但生产区域未知。**Supabase 托管区域没有中国大陆选项的代码/官方证据，实际项目区域又未补充；页面/API 托管也未知。
3. **模型商的 API 无训练、保存和删除规则未确认。**公开隐私政策与下游 API 场景不能直接等同。
4. **OCR 原始文件没有自助删除或自动到期。**删除源简历和历史不会删除 Storage 对象或 `user_files` 元数据。
5. **AI 标识未完整实现。**首页只有一般免责声明，结果项和 Markdown 下载没有专门的显式/隐式标识、内容凭证或导出日志。
6. **账号体系不完整。**有邮箱密码登录和服务端账号，但无公开注册、服务端会话撤销和账号注销入口。
7. **原生权限严重超配。**若直接发布 Android/iOS，会声明当前业务未使用的相机、麦克风、定位、通讯录、相册等权限，与 H5 协议不一致。

## 二、已由代码证实

### 1. 功能和数据流

- Taro H5 会把源简历保存到 `localStorage` 并通过 `/source-resume` 写入后端；
- 生成历史同时保存本地并通过 `/resume-history` 同步后端；
- PDF/图片在已登录时可直传 Supabase Storage，否则以 Base64 提交后端；
- 后端向 GLM OCR 发送完整文件 Base64；
- 后端向兼容 OpenAI API 的模型发送包含简历、JD 和中间结果的提示词；
- 默认模型地址为 DeepSeek，环境变量可以覆盖；
- Supabase 表保存完整简历、JD、优化内容和 ProcessResult；
- Harness 默认 7 日、最多 1,000 次运行，主要保存摘要、哈希、质量评估和运行元数据；
- 当前业务库源简历、历史、Storage 对象没有自动到期；
- 源简历和历史存在删除 API，但 Storage 对象和 Auth 账号无产品删除 API；
- 旧版 `frontend/Web` 仍会在 localStorage 保存简历/JD/结果，并将完整内容提交 `/api/v1/mvp/process`；
- 应用代码没有 Cookie、IndexedDB、Service Worker、广告、营销、统计、支付或错误监控 SDK；
- 当前 H5 没有调用相机、麦克风、定位、通讯录等原生权限；
- H5 两层请求日志都输出完整 `data`，可能把简历、JD 或文件 Base64 写入浏览器控制台；
- 历史 store 删除/清空会吞掉远端错误后清本地，可能使用户误以为服务端已删除。

## 三、根据配置推断，但不能当作已确认事实

| 推断 | 依据 | 不能确定的原因 | 所需证据 |
|---|---|---|---|
| 生产数据库使用 Supabase | 生产环境校验要求 `DATABASE_PROVIDER=supabase`、Auth 必开 | 无生产控制台和运行网络证据 | 部署配置、Supabase 项目截图、运行请求 |
| 生产大模型使用 DeepSeek | 代码默认地址/模型和 provider 名称 | `OPENAI_BASE_URL`、`AI_MODEL` 可覆盖 | 生产变量名称对应的脱敏配置、账单、合同 |
| 智谱处理在境内 | 智谱公开政策如此说明 | API 合同、底层云、备份和端点可另有安排 | 适用 API 数据条款、服务商书面确认 |
| DeepSeek API 数据在境内 | 面向直接服务的公开政策称境内 | 其政策明确下游开发者场景不由该政策覆盖 | Reffo 账号适用的 API 合同和地区确认 |
| 会发生个人信息出境 | Supabase 官方托管区域多为境外且无大陆区域 | 实际项目可能自托管或有特殊架构，仓库无法证明 | 项目区域、子处理者、托管架构和网络流量 |
| 生产域名为 `reffo.app`/`api.reffo.app` | 前端默认域名和配置 | DNS/部署控制台未知 | DNS、CDN、证书和托管控制台 |
| Render/Cloudflare 被使用 | 部署调研文档提出候选方案 | 调研文档不是部署事实 | 实际部署清单；确认前不得写进第三方清单 |

6. 智谱 GLM OCR 文件是否落盘、是否训练、日志内容、备份和删除协助；
7. 托管层是否设置 Cookie、记录 IP/User-Agent/请求正文，以及期限；
8. 生产数据库、Storage、Harness、访问日志和备份的实际保留任务是否正常运行；
9. 内部人员权限、审批、保密、访问审计、密钥轮换和应急预案；

11. AI 生成合成内容隐式标识是否满足配套强制性国家标准/平台检测；

14. 是否存在仓库外的日志、BI、客服、工单、邮件、备份或手工导出。

## 五、需要开发者补充或修复

### P0：正式上线阻断

| 问题 | 风险 | 必须完成的技术/产品动作 |
|---|---|---|
| 无首次协议确认和单独同意 | 用户可直接上传/生成，无法证明已阅读协议或对敏感信息、OCR、第三方 AI 作出有效选择 | 增加不预勾选首次确认；在任何网络请求前分开取得必要单独同意；拒绝时不得发送；记录版本和撤回 |
| 请求日志输出完整正文 | 浏览器控制台泄露完整简历、JD、文件 Base64，可能被扩展、远程调试或外部采集 | 两层日志都移除 `data`；生产默认关闭；错误/details 结构化白名单；增加日志泄露测试 |
| OCR Storage 对象无法删除且无到期 | 用户删除后原始简历仍长期存在；政策和实现冲突 | 增加按用户列举/删除对象和 `user_files` 元数据的后端接口；解析成功后短期自动清除；删除结果可验证；失败进入重试/工单 |
| 出境状态未知 | 无法完成专门告知、单独同意、影响评估和法定机制 | 锁定全部供应商地区；完成 PIPIA；按条件签标准合同/认证/安全评估；新增独立出境确认；未完成时禁止真实数据 |
| 模型 API 无训练/留存未知 | 真实简历可能被模型商保存或用于训练 | 签署无训练、短期/零留存、删除、事件通知和子处理条款；控制台固化设置并留证；不满足则更换服务商 |
| 运营者和联系人缺失 | 协议无法形成明确主体，用户无法行权 | 补全所有 `【待人工补充】`；验证邮箱/电话/工单能实际响应 |
| AI 生成内容标识不完整 | 可能不满足 2025-09-01 生效的标识规则 | 为结果页、网页复制、下载、API 输出和其他导出实现适用的显式/隐式标识；记录内容 ID、导出和标识状态；按标准检测 |
| 登录/注销不完整 | 退出被误解为注销，服务端账户与数据无法自助处理 | 明确账号来源；实现服务端 sign-out/revoke、账号注销和级联数据库/Storage 删除，或正式移除账号功能 |
| 生产托管未知 | 第三方、日志、地点和出境不能披露 | 形成数据资产和供应商台账；锁定部署并更新协议/清单 |
| 原生权限超配 | 原生发布会产生过度索权和协议不一致 | Android/iOS 发布前删去未使用权限和描述；按实际功能做原生隐私清单、SDK 和权限弹窗审核 |

### P1：上线前高优先级

| 问题 | 修复建议 |
|---|---|
| 业务数据无自动保存期限 | 制定并实现源简历、历史、文件、日志、备份的具体最短期限和到期任务；页面展示 |
| 同意仅存 localStorage | 登录态同步服务端审计记录，记录文案摘要/版本/接收方/撤回；防篡改并设置合规期限 |
| 现有 history store 吞远端删除失败 | 改为返回远端删除结果；失败不得清本地或显示成功；增加测试 |
| 退出登录只清本地 | 调 Supabase sign-out/revoke；清理内存和相关会话；说明是否全设备退出 |
| 开发/非认证 SQLite 使用共享 `DEV_USER_ID` | 禁止公网多人环境使用；启动时对非本地环境强制认证和用户隔离 |
| Harness 错误/评估可能带片段 | 对 error、issue、summary 做结构化白名单/PII 扫描；禁止原文；验证 7 日任务 |
| API Swagger 和 Harness 管理端点暴露 | 生产关闭或强认证、授权和网络限制；核验路由是否泄露诊断数据 |
| 敏感信息依赖用户自觉删除 | 上传前提供脱敏指引/检测；对身份证号、银行卡等做前端提示和后端阻断/脱敏策略 |
| 权利响应无工单 | 建立查阅、复制、更正、删除、限制、注销、投诉和逝者权利流程、身份核验和时限 |
| 旧版 `frontend/Web` 与新协议入口不一致 | 若仍部署，补相同协议、同意、删除、AI 标识和日志整改；否则停止部署并清理旧数据 |

## 九、法律依据与项目事实的边界

- 个人信息出境需专门告知、单独同意和 PIPIA，是法律要求；“Reffo 一定发生出境”目前只是基于 Supabase 区域的高概率风险，尚需生产证据。
- 敏感个人信息需要特定目的、充分必要、严格措施和单独同意，是法律要求；“每份简历全部属于敏感个人信息”不是准确结论，应按具体字段判断。
- 生成合成内容需要显式/隐式标识是现行规则；Reffo 当前尚无合格导出标识，未来具体实现是否满足配套标准，需要技术测试和法律复核。
- 第三方公开政策写“境内”或“最短必要”不等于 Reffo 账号已取得对应 API 合同承诺。
- 本地代码没有训练路径，不等于第三方绝不训练；需合同和设置证明。
