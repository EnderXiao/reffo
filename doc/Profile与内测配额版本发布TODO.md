## 需求边界

- Profile 页延续首页视觉主题：浅蓝到白色背景、现有卡片圆角、按钮、字体、头像和间距体系。
- 清除缓存只清理本机缓存，不清除 Landing 已完成标志位。
- 删除简历数据只删除数据库中生成的简历/历史结果，保留源简历。
- 内测每日生成次数按“简历分析第一步成功”计费；已有两个用户不限额，新注册用户使用配置化默认限制。
- GitHub 入口指向 `https://github.com/EnderXiao/reffo`。
- 版本页展示 tag 版本号、tag 描述和 `V1.0.0` 形式的版本号；没有正式 tag 时提供明确降级值。
- Render 发布改为 main 分支推送版本 tag 后触发 CI；版本号读取 tag 名，版本描述读取 tag description。

## 依赖与风险

- 配额扣减必须和“第一步成功”事件绑定；提前扣减会误伤失败请求，延后扣减会产生绕过窗口。
- 删除接口必须按用户隔离；Supabase RLS、SQLite 查询条件和历史数据迁移都需单独验证。
- Markdown 内容进入构建产物后需防止路径在 Render/静态 H5 环境失效。
- tag 触发发布依赖 GitHub Actions 与 Render 权限；保留旧部署回滚入口，先在非生产 tag 验证。
- 数据库迁移先备份、可回滚，再切换配额校验；已有不限额用户必须有可审计名单或标记。
