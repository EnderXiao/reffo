# Reffo 宽屏响应式布局重构方案

## 目标

让所有 H5 页面在宽屏设备上保持移动端的内容比例与阅读节奏：背景铺满视口，业务内容通过居中容器收敛到可控宽度；窗口宽高变化时使用比例和 flex/grid 自适应。卡片舞台允许使用 absolute 实现堆叠和动画，但卡片内部内容统一使用 flex/grid，保证按钮、图标和文本稳定留在卡片内。

## 现状问题

- 页面根容器、文案、按钮和卡片同时使用视口级 absolute 定位。
- `vw`、`dvh` 与设计稿固定坐标混用，宽屏时横向距离被放大。
- landing 队列动画把浏览器视口当作卡片舞台，后续步骤会偏移到屏幕边缘。
- 各页面分别维护桌面端补丁，缺少统一的内容容器契约。

## 目标结构

```text
全屏页面背景
└── .reffo-page-frame（居中、按比例约束的 flex 容器）
    ├── header / logo
    ├── main（flex/grid）
    ├── card-stage（relative，负责卡片堆叠）
    │   └── card（absolute 仅用于堆叠）
    │       └── card-content（flex/grid）
    └── footer / action
```

## 设计规则

1. 页面布局优先使用 flex、grid、`clamp()`、`min()`、`max()` 和 `aspect-ratio`。
2. 页面背景可以是全屏 absolute；业务内容必须位于统一内容容器内。
3. 卡片舞台使用 `position: relative`，卡片堆叠和 3D 动画可以使用 `absolute`。
4. 卡片内部的分区、按钮、图标、标签和文本使用 flex/grid，不用视口单位定位。
5. 动画位移只相对于卡片舞台或卡片自身，禁止在业务动画中直接使用 `vw` 作为设计坐标。
6. 桌面端通过内容容器产生两侧留白，不通过放大卡片或拉伸文字填满屏幕。
7. 移动端行为保持现有设计稿比例，低高度窗口优先压缩间距和卡片缩放。

## 分阶段实施

- [x] 单元 0：建立方案、TODO 和验证边界。
- [ ] 单元 1：抽取并接入全局 H5 页面内容容器契约，统一宽屏背景与内容壳层。
- [ ] 单元 2：重构首页与 landing 首屏的 header、文案、操作区为 flex 布局。
- [ ] 单元 3：重构 landing 队列及后续步骤的舞台坐标，移除视口级 `vw` 动画定位。
- [ ] 单元 4：重构 create、result、complete 页面内容壳层和卡片内部 flex 布局。
- [ ] 单元 5：清理旧桌面补丁，补充响应式回归用例并完成 H5 多视口验证。

## 风险与回滚

每个单元保持独立提交。若某页面动画出现回归，可只回滚该单元；卡片舞台的 absolute 动画实现保留，优先回滚容器或坐标层变更。

## 验证矩阵

- 移动端：393×852、375×812。
- 宽屏：1280×800、1440×900。
- 低高度：1280×600。
- 页面：首页、landing 全流程、create、result、complete。
- 命令：`corepack pnpm@10.33.2 build:h5`，必要时运行相关 Jest 测试。
