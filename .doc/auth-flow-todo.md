# Reffo 登录注册流程 TODO

## 目标

在 `pages/auth/index` 单一路由内完成登录、注册和邮箱验证码确认。页面复用首页卡片的品牌材质语言，背景、纹理和表单容器保持同一组 DOM，仅切换流程内容和状态，避免路由跳转造成闪烁。

## Supabase 能力结论

- [x] 邮箱密码登录：支持 `POST /auth/v1/token?grant_type=password`。
- [x] 邮箱密码注册：支持 `POST /auth/v1/signup`。
- [x] 注册验证码校验：支持 `POST /auth/v1/verify`，使用 `type: signup` 和邮箱 OTP。
- [x] 重新发送注册验证码：支持 `POST /auth/v1/resend`，使用 `type: signup`。
- [x] GitHub、Google、Apple OAuth：支持 `/auth/v1/authorize?provider=...`，但各 Provider 需要先在 Supabase 控制台配置 Client ID、Secret 和回调地址。
- [ ] Supabase 邮件模板需展示 `{{ .Token }}`，否则默认邮件可能只展示确认链接。
- [x] OTP 位数和重发冷却由后端返回，配置项为 `AUTH_OTP_LENGTH` 与 `AUTH_OTP_RESEND_SECONDS`；需与 Supabase Auth 邮件模板和项目设置保持一致。
- [x] 邮箱是否已注册不能依赖公开登录错误判断。公开登录接口会统一返回无效凭据，需由 Reffo 后端使用 Supabase Secret Key 查询。
- [ ] 邮箱存在检查会暴露账号是否注册，正式上线前需增加限流、验证码或风控，避免邮箱枚举。
- [x] 前端和请求适配器日志对邮箱、密码、验证码和 Token 脱敏。
- [x] HTTPS 之上增加应用层混合加密：AES-256-GCM 加密认证载荷，RSA-OAEP SHA-256 加密 AES 密钥；浏览器认证请求体不出现明文邮箱、密码或 recovery token。
- [x] 服务端校验密钥 ID、2 分钟时间窗口和一次性 nonce，拒绝明文密码载荷及重放请求；Supabase 仍负责密码哈希和账号存储。

## 视觉方案

### Visual thesis

整页是一张固定 Reffo 蓝色主题卡片：低对比品牌 Logo 随机纹理铺满背景，输入区像首页卡片底部信息区一样覆盖单层毛玻璃，视觉稳定、品牌明确。

### Content plan

- 品牌区：Reffo 标志、当前步骤标题、短说明。
- 工作区：邮箱、密码、确认密码或 OTP 输入。
- 主操作：登录、注册、自动验证码确认。
- 辅助操作：返回、重新发送验证码、GitHub / Google / Apple 登录。

### Interaction thesis

- 背景、纹理和毛玻璃容器保持不卸载；登录、注册和验证码面板横向平移并淡入淡出。
- 标题随步骤轻微上移切换，主按钮状态通过颜色和进度变化反馈。
- OTP 每格稳定占位，输入满 6 位自动校验；失败时轻微水平震动并保留输入焦点。

## 业务流程

### 登录

- [x] 校验邮箱和密码必填、邮箱格式正确。
- [x] 点击登录先检查邮箱是否存在。
- [x] 邮箱不存在时复用通用消息弹窗，询问是否注册。
- [x] 取消后停留登录页；确认后进入注册状态，并回填邮箱和密码。
- [x] 邮箱存在时执行密码登录；成功后恢复来源页或回首页。
- [x] 密码错误时保留邮箱并展示明确错误。

### 注册

- [x] 展示邮箱、密码、再次确认密码。
- [x] 邮箱和密码从登录页自动带入，允许修改。
- [x] 再次确认密码必须由用户输入。
- [x] 校验邮箱格式、密码长度和两次密码一致。
- [x] 提交前重新检查邮箱是否存在。
- [x] 已存在时询问是否直接登录；确认后返回登录并回填邮箱，取消仅关闭弹窗。
- [x] 未存在时调用 Supabase 注册并进入验证码状态。

### 验证码

- [x] 按后端返回位数展示独立视觉输入格，底层使用单一真实输入框以兼容粘贴和移动端键盘。
- [x] 输入满后端返回位数自动调用 Supabase `verify`。
- [x] 校验通过后持久化 Session，直接完成登录。
- [x] 校验失败时复用消息组件提示，并允许重新输入。
- [x] 显示后端返回的重发倒计时；结束后显示“重新发送验证码”。
- [x] 重发成功后重新开始倒计时。

### 密码重置与修改

- [x] 登录页提供忘记密码入口，使用 Supabase recovery OTP，不依赖跨路由邮件链接回跳。
- [x] recovery OTP 校验通过后进入同路由新密码状态。
- [x] 新密码和 recovery access token 使用应用层加密 Envelope 提交。
- [x] 已登录账号支持使用当前 access token 修改密码，复用同一密文接口。
- [x] 登录、注册、重置密码、修改密码接口均拒绝明文密码请求体。

### 第三方登录

- [x] 提供 GitHub、Google、Apple 登录入口。
- [x] H5 使用 Supabase OAuth authorize URL 和当前 Auth 页面回调地址。
- [x] Auth 页面启动时解析 OAuth 回调中的 Session 并持久化。
- [ ] RN / 小程序后续补深链和平台授权适配；本轮保持明确降级提示。
